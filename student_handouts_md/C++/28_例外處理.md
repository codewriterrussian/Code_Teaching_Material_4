![Lesson 27 → Lesson 28 過渡圖](images/lesson_28/CPP_Lesson_28_img00_normal_flow_to_exception.png)
> 這堂課的重點：使用 C++ 例外處理機制表示「函式無法正常完成工作」的情況。你會學習 `try`、`catch`、`throw`、標準例外類別、自訂例外、堆疊展開、RAII、建構子失敗、重新拋出、`noexcept` 與例外安全保證。

> 例外不是一般流程控制工具。它適合處理目前函式無法正常完成、而呼叫端可能有能力處理的異常狀況。一般輸入判斷、搜尋不到、布林條件與可預期分支，不一定要使用例外。

## Section II. 今天的學習方式

1. 每次遇到失敗先問：
   ```text
   這是正常可預期結果，還是函式無法履行主要工作？
   ```
2. 丟出具有意義的標準例外類型。
3. 捕捉標準例外時優先使用：
   ```cpp
   catch (const std::exception& error)
   ```
4. Catch 順序：具體型別在前，基底型別在後。
5. 只有在能處理、轉換或記錄時才 catch。
6. 需要重新拋出原例外時使用 `throw;`。
7. 資源清理交給 RAII 物件。
8. 解構子不應讓例外向外傳出。
9. Try block 只包住使用同一錯誤處理策略的操作。
10. 所有合法完整程式使用嚴格 C++17 選項檢查。

## Section III. 核心語法對照

| 語法 | 用途 |
| --- | --- |
| `throw exceptionObject;` | 拋出例外 |
| `try { ... }` | 包住可能拋出例外的操作 |
| `catch (const exception& error)` | 捕捉標準例外 |
| `catch (...)` | 捕捉任何例外 |
| `throw;` | 重新拋出目前例外 |
| `error.what()` | 取得錯誤訊息 |
| `runtime_error("message")` | 執行期失敗 |
| `invalid_argument("message")` | 參數不合法 |
| `out_of_range("message")` | 範圍或索引錯誤 |
| `void function() noexcept` | 宣告函式不讓例外離開 |
| `noexcept(expression)` | 編譯期查詢運算式是否不拋出 |
| `assert(condition)` | 偵錯期檢查內部假設 |
| `vector.at(index)` | 有界限檢查的容器存取 |
| `stoi(text)` | 字串轉整數，可能拋出例外 |

## Section IV. Throw

![Throw 後程式不會繼續往下](images/lesson_28/CPP_Lesson_28_img03_throw_stops_normal_flow.png)
```cpp
throw std::runtime_error(
    "Unable to complete operation."

```

Throw 後目前正常流程停止，控制權開始尋找相符的 catch handler。

## Section V. 完整第一個範例

```cpp
// VALIDATE
#include <iostream>
#include <stdexcept>
using namespace std;

double divide(
    double numerator,
    double denominator
) {
    if (denominator == 0.0) {
        throw invalid_argument(
            "Denominator cannot be zero."
        );
    }

    return numerator / denominator;
}

int main() {
    try {
        cout << divide(10.0, 0.0)
             << '\n';
    } catch (
        const invalid_argument& error
    ) {
        cout << "Input error: "
             << error.what()
             << '\n';
    }

    return 0;
}
```

# Part D：Catch by Const Reference

![Catch by Value vs Catch by Const Reference](images/lesson_28/CPP_Lesson_28_img08_catch_value_vs_const_reference.png)
## Section X. 建議形式

```cpp
catch (
    const exception& error
)
```

優點：

- 避免不必要複製。
- 避免例外 slicing。
- 保留動態型別。
- 可以安全呼叫 `what()`。

## Section XI. 完整基底捕捉

```cpp
// VALIDATE
#include <iostream>
#include <stdexcept>
using namespace std;

void validateAge(int age) {
    if (age < 0) {
        throw invalid_argument(
            "Age cannot be negative."
        );
    }

    if (age > 150) {
        throw out_of_range(
            "Age is outside the supported range."
        );
    }
}

int main() {
    try {
        validateAge(200);
    } catch (
        const exception& error
    ) {
        cout << error.what()
             << '\n';
    }

    return 0;
}
```

```cpp

    // 捕捉任何例外

```

## Section XV. `throw;`

![throw; vs throw error;](images/lesson_28/CPP_Lesson_28_img11_rethrow_vs_throw_variable.png)
在 catch 中使用：

```cpp
throw;
```

會重新拋出目前正在處理的原例外。

## Section XVI. 完整重新拋出

```cpp
// VALIDATE
#include <iostream>
#include <stdexcept>
using namespace std;

void lowLevelOperation() {
    throw runtime_error(
        "Storage service unavailable."
    );
}

void middleLevelOperation() {
    try {
        lowLevelOperation();
    } catch (
        const exception& error
    ) {
        cout << "Middle layer log: "
             << error.what()
             << '\n';

        throw;
    }
}

int main() {
    try {
        middleLevelOperation();
    } catch (
        const exception& error
    ) {
        cout << "Top layer: "
             << error.what()
             << '\n';
    }

    return 0;
}
```

`throw error;` 可能依 catch 變數靜態型別重新建立例外；重新拋出原例外應使用 `throw;`。

# Part G：Stack Unwinding

![Stack Unwinding 核心圖](images/lesson_28/CPP_Lesson_28_img12_stack_unwinding.png)
## Section XVII. 自動解構

例外向上傳遞時，已完整建立的區域物件會依反序解構，這稱為 stack unwinding。

## Section XVIII. 完整追蹤範例

```cpp
// VALIDATE
#include <iostream>
#include <stdexcept>
#include <string>
using namespace std;

class Tracer {
public:
    explicit Tracer(
        const string& initialName
    )
        : nameValue(initialName) {
        cout << "Construct "
             << nameValue
             << '\n';
    }

    ~Tracer() {
        cout << "Destroy "
             << nameValue
             << '\n';
    }

private:
    string nameValue;
};

void operation() {
    Tracer first("first");
    Tracer second("second");

    throw runtime_error(
        "Operation failed."
    );
}

int main() {
    try {
        operation();
    } catch (
        const exception& error
    ) {
        cout << "Caught: "
             << error.what()
             << '\n';
    }

    return 0;
}
```

# Part I：建構子拋出例外

![Constructor Throw：物件沒有完成建立](images/lesson_28/CPP_Lesson_28_img16_constructor_throw_incomplete_object.png)

![Constructor Validation vs Setter 修補](images/lesson_28/CPP_Lesson_28_img42_constructor_invariant_exception.png)
## Section XXII. 阻止無效物件建立

建構參數無法形成有效物件時，建構子可以拋出例外。

## Section XXIII. 完整建構子驗證

```cpp
// VALIDATE
#include <iostream>
#include <stdexcept>
#include <string>
using namespace std;

class BankAccount {
public:
    BankAccount(
        const string& initialOwner,
        double initialBalance
    )
        : ownerName(initialOwner),
          balanceValue(
              validateBalance(
                  initialBalance
              )
          ) {
        if (ownerName.empty()) {
            throw invalid_argument(
                "Owner name cannot be empty."
            );
        }
    }

    const string& owner() const {
        return ownerName;
    }

    double balance() const {
        return balanceValue;
    }

private:
    static double validateBalance(
        double balance
    ) {
        if (balance < 0.0) {
            throw invalid_argument(
                "Initial balance cannot be negative."
            );
        }

        return balance;
    }

    string ownerName;
    double balanceValue;
};

int main() {
    try {
        BankAccount account(
            "Amy",
            -100.0
        );

        cout << account.owner()
             << '\n';
    } catch (
        const exception& error
    ) {
        cout << error.what()
             << '\n';
    }

    return 0;
}
```

該物件沒有完成建立，因此不會執行完整物件解構子；已完成建立的成員仍會被清理。

```cpp
// VALIDATE
#include <iostream>
#include <stdexcept>
using namespace std;

class AccountNotFoundError :
    public runtime_error {
public:
    explicit AccountNotFoundError(
        int missingId
    )

        const AccountNotFoundError& error

             << " ID: "
             << error.accountId()
             << '\n';
    }

    return 0;
}
```

## Section XXVII. 低階錯誤轉成領域錯誤

底層錯誤不一定適合直接暴露給上層。可在理解其意義的邊界轉成領域例外。

## Section XXVIII. 完整轉換範例

```cpp
// VALIDATE

#include <stdexcept>
using namespace std;

class CustomerLoadError :
    public runtime_error {
public:
    CustomerLoadError()
        : runtime_error(
              "Unable to load customer."
          ) {
    }
};

void readStorage() {
    throw runtime_error(
        "Low-level storage failure."
    );
}

void loadCustomer() {
    try {
        readStorage();
    } catch (
        const runtime_error&
    ) {
        throw CustomerLoadError();
    }
}

int main() {
    try {
        loadCustomer();
    } catch (
        const CustomerLoadError& error
    ) {
        cout << error.what()
             << '\n';
    }

    return 0;
}
```

## Section XXXII. 完整解析範例

```cpp
// VALIDATE
#include <iostream>
#include <stdexcept>
#include <string>
using namespace std;

int parseInteger(
    const string& text
) {
    size_t processed = 0;

    int value = stoi(
        text,
        &processed
    );

    if (processed != text.size()) {
        throw invalid_argument(
            "The entire string is not an integer."
        );
    }

    return value;
}

int main() {
    try {
        cout << parseInteger(
                    "123abc"
                )
             << '\n';
    } catch (
        const invalid_argument& error
    ) {
        cout << "Invalid: "
             << error.what()
             << '\n';
    } catch (
        const out_of_range& error
    ) {
        cout << "Range: "
             << error.what()
             << '\n';
    }

    return 0;
}
```

# Part Q：解構子與例外

![Destructor + Exception = 特別危險](images/lesson_28/CPP_Lesson_28_img25_destructor_exception_danger.png)
## Section XXXVII. 解構子不應拋出

如果 stack unwinding 期間解構子再拋出第二個例外，程式通常會終止。

清理可能失敗時，常見設計：

1. 提供明確 `close()`。
2. 呼叫者在正常流程處理 close 錯誤。

## Section XXXVIII. 完整安全清理概念

```cpp
class Connection {
public:
    bool close() {
        if (!openValue) {
            return true;
        }

        openValue = false;
        return true;
    }

    ~Connection() noexcept {
        if (openValue) {
            openValue = false;
        }
    }

private:
    bool openValue = true;
};

int main() {
    Connection connection;

    cout << boolalpha
         << connection.close()
         << '\n';

    return 0;
}
```

## Section XLIII. 四種保證

### No-Throw Guarantee

操作保證不拋出。

### Strong Guarantee

操作失敗時，物件狀態保持和操作前相同。

### Basic Guarantee

操作失敗時不洩漏資源，物件仍有效，但內容可能改變。

失敗後狀態可能損壞，應避免。

# Part U：先計算後提交

![Strong Guarantee：先計算後提交](images/lesson_28/CPP_Lesson_28_img30_strong_guarantee_commit_pattern.png)
## Section XLIV. Strong Guarantee 策略

1. 在局部暫存物件完成可能失敗的工作。
2. 全部成功後才提交正式狀態。

## Section XLV. 完整先計算後提交

```cpp
// VALIDATE
#include <iostream>
#include <stdexcept>
#include <vector>
using namespace std;

class ScoreCollection {
public:
    void replaceScores(
        const vector<int>& newScores
    ) {
        vector<int> validated;

        validated.reserve(
            newScores.size()
        );

        for (int score : newScores) {
            if (
                score < 0 ||
                score > 100
            ) {
                throw invalid_argument(
                    "Score must be between 0 and 100."
                );
            }

            validated.push_back(score);
        }

        scores = validated;
    }

    vector<int>::size_type
    size() const noexcept {
        return scores.size();
    }

private:
    vector<int> scores;
};

int main() {
    ScoreCollection collection;

    try {
        collection.replaceScores(
            {
                90,
                110,
                80
            }
        );
    } catch (
        const exception& error
    ) {
        cout << error.what()
             << '\n';
    }

    cout << collection.size()
         << '\n';

    return 0;
}
```

# Part X：Exception-Neutral Template

![Exception-Neutral Template](images/lesson_28/CPP_Lesson_28_img35_exception_neutral_template.png)
## Section LI. 不理解就向上傳遞

Template 或一般基礎元件通常不應任意捕捉並吞掉 callable 的例外。

## Section LII. 完整例外中立範例

```cpp
// VALIDATE
#include <iostream>
#include <stdexcept>
#include <vector>
using namespace std;

template <
    typename Iterator,
    typename Operation
>
void applyToRange(
    Iterator first,
    Iterator last,
    Operation operation
) {
    while (first != last) {
        operation(*first);
        ++first;
    }
}

int main() {
    vector<int> values{
        1,
        2,
        -1,
        3
    };

    try {
        applyToRange(
            values.cbegin(),
            values.cend(),
            [](int value) {
                if (value < 0) {
                    throw invalid_argument(
                        "Negative value is not allowed."
                    );
                }

                cout << value
                     << '\n';
            }
        );
    } catch (
        const exception& error
    ) {
        cout << error.what()
             << '\n';
    }

    return 0;
}
```

# Part AD：常見錯誤提醒

## Section LIX. 常見錯誤

1. 使用例外處理所有一般條件分支。

3. 丟出整數。

10. Catch-all 後不記錄也不處理。
11. Throw 後期待後續程式執行。
12. 手動資源在 throw 路徑洩漏。
13. 建構子失敗時假設完整解構子會執行。
14. 解構子向外拋出例外。
15. Noexcept 函式讓例外離開。
16. 誤以為 `noexcept` 會自動捕捉例外。

18. 使用 exception 表示正常搜尋不到。
19. 使用 vector `operator[]` 期待範圍檢查。
20. `stoi()` 只捕捉一種可能例外。

22. 自訂例外沒有繼承標準例外。

27. 修改物件一半後才執行可能失敗的操作。

```mermaid
    B -- 是 --> D[建立並 throw 例外]
    D --> E[尋找目前作用域 catch]
    E --> F{有相符 handler 嗎}
    F -- 是 --> G[執行 catch]
    F -- 否 --> H[Stack unwinding]
    H --> I[上一層繼續搜尋]
    I --> F
```

### 2. Catch 順序

```mermaid
flowchart TD
    A[收到例外] --> B[檢查最具體 catch]
    B --> C{匹配嗎}
    C -- 是 --> D[執行 handler]
    C -- 否 --> E[檢查較一般基底 catch]
    E --> F{匹配嗎}
    F -- 是 --> D
    F -- 否 --> G[檢查 catch all]
    G --> H{存在嗎}
    H -- 是 --> D
    H -- 否 --> I[向上傳遞或 terminate]
```

### 3. Stack Unwinding

```mermaid
flowchart TD
    A[例外離開作用域] --> B[銷毀最後完成建立物件]
    B --> C[依反序銷毀其他區域物件]
    C --> D[離開目前函式]
    D --> E[上一層尋找 handler]
```

### 4. 錯誤策略選擇

```mermaid
flowchart TD
    A[操作可能失敗] --> B{失敗是常見正常結果嗎}
    B -- 是 --> C{只有有或沒有嗎}
    C -- 是 --> D[optional iterator]
    C -- 否 --> E[bool enum 結果型別]
    B -- 否 --> F{目前層能恢復嗎}
    F -- 是 --> G[直接處理]
    F -- 否 --> H[throw exception]
```

### 5. Strong Guarantee

```mermaid
flowchart TD
    A[收到新資料] --> B[暫存物件驗證與計算]
    B --> C{全部成功嗎}
    C -- 否 --> D[暫存物件自動清理]
    D --> E[原物件保持不變]
    C -- 是 --> F[提交或 swap]
    F --> G[更新正式狀態]
```

### 6. Noexcept

```mermaid
flowchart TD
    A[呼叫 noexcept 函式] --> B{函式內發生例外嗎}
    B -- 否 --> C[正常完成]
    B -- 是 --> D{函式內已處理嗎}
    D -- 是 --> C
    D -- 否 --> E[std terminate]
```

### 7. 自訂例外

```mermaid
flowchart TD
    A[需要領域錯誤] --> B{標準例外已足夠嗎}
    B -- 是 --> C[使用標準類型]
    B -- 否 --> D[繼承 runtime error 或 logic error]
    D --> E[加入必要上下文]
    E --> F[依 const reference 捕捉]
```

### 8. 例外邊界

```mermaid
flowchart TD
    A[低階函式失敗] --> B{本層能恢復嗎}
    B -- 是 --> C[處理並繼續]
    B -- 否 --> D{需要轉成領域例外嗎}
    D -- 是 --> E[Exception translation]
    D -- 否 --> F[向上傳遞]
    E --> F
    F --> G[高層 exception boundary]
    G --> H[記錄並顯示安全訊息]
```
