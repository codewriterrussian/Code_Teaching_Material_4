# Lesson 15：Scope and Lifetime 作用域與生命週期

> 這堂課的重點：分清楚「名稱在哪裡可以使用」與「物件在記憶體中存在多久」。作用域 scope 管理名稱的可見範圍；生命週期 lifetime 管理物件從建立到銷毀的期間。兩者彼此相關，但不是同一件事。

> 本章會介紹區塊作用域、函式作用域、迴圈作用域、命名空間作用域、全域名稱、變數遮蔽、作用域解析運算子 `::`、自動儲存期、靜態儲存期、`static` 區域變數、暫時物件、參考與生命週期，以及懸空參考。動態配置物件的完整管理會留到後續動態記憶體章節。

## Section II. 今天的學習方式

1. 每個變數先回答三個問題：
   ```text
   名稱在哪裡可見？
   物件何時建立？
   物件何時銷毀？
   ```
2. 看到大括號時，標出區塊邊界。
3. 看到同名變數時，先判斷目前所在的最內層作用域。
4. 作用域題只追蹤「名稱可否使用」。
5. 生命週期題追蹤「物件是否仍存在」。
6. `static` 區域變數要分開記錄：
   ```text
   名稱：只在函式內可見
   物件：整個程式期間持續存在
   ```
7. 參考題一定檢查被參考物件是否仍存在。
8. 回傳參考題一定確認來源不是即將銷毀的區域物件。
9. 暫時物件題先找完整表示式的結尾分號。
10. 遮蔽題不要只看名稱，要找最近的宣告。
11. 所有合法完整程式使用嚴格 C++17 選項檢查。
12. 會產生未定義行為的範例只供分析，不執行。

## Section III. 核心術語對照

| 術語 | 意義 |
| --- | --- |
| Scope 作用域 | 名稱可以被程式使用的範圍 |
| Lifetime 生命週期 | 物件從建立到銷毀的期間 |
| Block scope 區塊作用域 | 一對大括號建立的可見範圍 |
| Local variable 區域變數 | 宣告在函式或區塊內的變數 |
| Global name 全域名稱 | 宣告在所有函式外的名稱 |
| Namespace scope 命名空間作用域 | 位於命名空間中的名稱範圍 |
| Shadowing 遮蔽 | 內層同名名稱暫時隱藏外層名稱 |
| Automatic storage duration 自動儲存期 | 進入區塊建立、離開區塊銷毀 |
| Static storage duration 靜態儲存期 | 通常從程式開始到程式結束存在 |
| Temporary object 暫時物件 | 表示式計算過程中產生的短期物件 |
| Dangling reference 懸空參考 | 參考指向已不存在的物件 |
| Linkage 連結 | 同一名稱是否能跨作用域或來源檔代表同一實體 |
| `::` | 作用域解析運算子 |
| `static` local | 區域作用域、靜態儲存期 |
| `constexpr` | 可在編譯期間求值的常數宣告 |

## Section IV. 作用域管理名稱

```cpp
{
    int value = 10;
    cout << value << '\n';
}
```

名稱 `value` 只在這一對大括號內可見。

## Section V. 生命週期管理物件

一般區域變數：

```text
執行到宣告位置
→ 建立並初始化
→ 使用
→ 離開區塊
→ 銷毀
```

---

## Section VI. 比較表

| 問題 | 屬於 |
| --- | --- |
| 這裡能不能寫 `value`？ | 作用域 |
| `value` 所代表的物件還存在嗎？ | 生命週期 |
| 內層同名變數會用哪一個？ | 作用域 |
| 函式結束後區域變數是否仍存在？ | 生命週期 |
| `static` 區域變數能否在其他函式直接使用？ | 作用域 |
| `static` 區域變數是否保留前次值？ | 生命週期 |

---

## Section VII. 關鍵差異

`static` 區域變數最能說明兩者不同：

```cpp
void example() {
    static int count = 0;
}
```

- 名稱 `count` 只在 `example()` 中可見。
- 物件卻持續存在到程式結束。

# Part B：區塊作用域

## Section VIII. 大括號建立區塊

```cpp
{
    int value = 10;
}
```

`value` 的作用域從宣告點開始，到右大括號結束。

---

## Section IX. 完整區塊範例

```cpp
// VALIDATE
#include <iostream>
using namespace std;

int main() {
    int outerValue = 10;

    {
        int innerValue = 20;

        cout << outerValue
             << " "
             << innerValue
             << '\n';
    }

    cout << outerValue
         << '\n';

    return 0;
}
```

`innerValue` 離開內層區塊後不可再使用。

---

## Section X. 內層可以看見外層

```cpp
int outerValue = 10;

{
    cout << outerValue;
}
```

內層作用域通常可以存取外層已宣告的名稱。

---

## Section XI. 外層看不見內層

```cpp
{
    int innerValue = 20;
}

/* cout << innerValue; */
```

離開區塊後，名稱不再可見，而且一般區域物件也已銷毀。

# Part C：名稱從宣告點開始可見

## Section XII. 宣告之前不能使用

不合法概念：

```cpp
/* cout << value; */

```

名稱通常要等宣告出現後才進入作用域。

---

## Section XIII. 同一區塊中的宣告點

```cpp
int first = 10;
int second = first + 5;
```

`first` 已經宣告，因此可以用來初始化 `second`。

---

## Section XIV. 自我初始化問題

危險概念：

```cpp
int value = value;
```

右側名稱可能指向正在宣告但尚未正確初始化的物件，結果不是想要的「使用外層值」。

應避免使用相同名稱造成混淆。

# Part D：`if` 與 `else` 的作用域

## Section XV. `if` 區塊

```cpp
if (condition) {
    int result = 10;
}
```

`result` 只在 `if` 區塊內可見。

---

## Section XVI. `if` 與 `else` 是不同區塊

```cpp
if (condition) {
    int value = 10;
} else {
    int value = 20;
}
```

兩個 `value` 是不同物件。

---

## Section XVII. 完整分支範例

```cpp
// VALIDATE
#include <iostream>
using namespace std;

int main() {
    int number;
    cin >> number;

    if (number >= 0) {
        int absoluteValue = number;

        cout << absoluteValue
             << '\n';
    } else {
        int absoluteValue = -number;

        cout << absoluteValue
             << '\n';
    }

    return 0;
}
```

兩個 `absoluteValue` 位於不同區塊，不會同時存在。

# Part E：`for` 迴圈變數的作用域

## Section XVIII. 初始化區宣告

```cpp
for (int index = 0; index < 5; ++index) {
    cout << index << '\n';
}
```

`index` 可見於：

- 條件區
- 更新區
- 迴圈主體

---

## Section XIX. 迴圈結束後

不合法概念：

```cpp
for (int index = 0; index < 5; ++index) {
    cout << index;
}

/* cout << index; */
```

`index` 已離開作用域。

---

## Section XX. 完整 `for` 作用域範例

```cpp
// VALIDATE
#include <iostream>
using namespace std;

int main() {
    for (int index = 0; index < 3; ++index) {
        int square =
            index * index;

        cout << square
             << '\n';
    }

    return 0;
}
```

每一輪都會建立新的 `square` 物件，並在該輪主體結束時銷毀。

---

## Section XXI. Range-Based `for`

```cpp
for (int value : values) {
    // value 只在本輪迴圈主體內使用
}
```

每輪的 `value` 都是該輪迴圈變數。

# Part G：函式作用域

## Section XXIV. 參數是區域名稱

```cpp
int square(int number) {
    return number * number;
}
```

`number` 只在 `square()` 函式內可見。

---

## Section XXV. 不同函式可以重複名稱

```cpp
void first(int value) {
    cout << value;
}

void second(int value) {
    cout << value;
}
```

兩個 `value` 位於不同函式作用域。

---

## Section XXVI. 每次呼叫都有自己的物件

```cpp
int addOne(int value) {
    ++value;
    return value;
}
```

每次呼叫都建立新的參數 `value`。

## Section XXVII. 完整函式區域範例

```cpp
// VALIDATE
#include <iostream>
using namespace std;

int addOne(int value) {
    int result =
        value + 1;

    return result;
}

int main() {
    cout << addOne(5)
         << '\n';

    cout << addOne(10)
         << '\n';

    return 0;
}
```

兩次呼叫的 `value` 與 `result` 是不同物件。

## Section XXIX. 完整命名空間範例

```cpp
// VALIDATE
#include <iostream>
using namespace std;

namespace School {
    constexpr int passingScore = 60;

    bool isPassing(int score) {
        return
            score >= passingScore;
    }

    int score;
    cin >> score;

```

# Part I：全域名稱

## Section XXXII. 宣告在所有函式外

```cpp
int globalCount = 0;
```

名稱可在後續適當位置的函式中使用。

物件通常具有靜態儲存期。

---

## Section XXXIII. 完整全域狀態範例

```cpp
// VALIDATE
#include <iostream>
using namespace std;

int globalCount = 0;

void recordCall() {
    ++globalCount;
}

int main() {
    recordCall();
    recordCall();

    cout << globalCount
         << '\n';

    return 0;
}
```

輸出：

```text
2
```

---

## Section XXXIV. 全域變數的風險

任何可存取它的函式都可能修改：

```cpp
globalCount
```

因此：

- 修改來源不易追蹤。
- 函式依賴隱藏狀態。
- 測試較困難。
- 多個模組容易互相影響。

---

## Section XXXV. 優先使用資料流

較清楚：

```cpp
int recordCall(int count) {
    return count + 1;
}
```

或將狀態交給物件管理。

初學階段應少用可修改全域變數。

# Part J：作用域解析運算子 `::`

## Section XXXVI. 命名空間名稱

```cpp
School::passingScore
```

`::` 指定從 `School` 命名空間尋找名稱。

---

## Section XXXVII. 全域名稱

若區域名稱遮蔽全域名稱：

```cpp
int value = 10;

int main() {
    int value = 20;

    cout << value;
    cout << ::value;
}
```

- `value`：最內層區域名稱。
- `::value`：全域名稱。

---

## Section XXXVIII. 不建議依賴同名

雖然 `::` 可以存取全域名稱，但更好的方式通常是：

- 使用不同且有意義的名稱。
- 將常數放入命名空間。
- 避免可修改全域狀態。
- 啟用 `-Wshadow`。

## Section XL. 外層物件仍存在

# Part V：安全回傳參考

## Section LXXVII. 回傳參考參數

    int& second

只要呼叫者的物件仍存在，回傳參考就可以有效。

## Section LXXVIII. 完整安全參考回傳

```cpp
// VALIDATE

    int& first,
    int& second

        return first;
    }

    return second;
}

int main() {
    int first = 10;
    int second = 20;

    larger(first, second) =
        100;

    cout << first
         << " "
         << second
         << '\n';

    return 0;
}
```

# Part AG：常見錯誤提醒

## Section CII. 常見錯誤

1. 混淆作用域與生命週期。
2. 在宣告前使用名稱。
3. 在區塊外使用區域變數。
4. 在迴圈後使用初始化區變數。
5. 認為每輪迴圈使用同一個自動區域物件。
6. 忘記參數也是區域變數。
7. 不必要地重複使用相同變數名稱。
8. 變數遮蔽造成讀取錯誤。
9. 自我初始化同名變數。
10. 關閉或忽略 `-Wshadow` 警告。
11. 過度使用可修改全域變數。
12. 以為全域名稱與全域物件生命週期完全等同於所有情況。
13. 認為 `static` 區域名稱在函式外也可見。
14. 以為 `static` 區域變數每次呼叫重新初始化。
15. 使用 `static` 隱藏過多函式狀態。
16. 忘記區域自動變數在函式結束時銷毀。
17. 回傳區域變數參考。
18. 回傳區域變數位址。
19. 保存比原物件活得更久的參考。
20. 認為參考會自動延長所有物件生命週期。
21. 過度概括 `const` 參考的暫時值延長規則。
22. 把暫時物件參考保存到呼叫結束後。
23. 回傳非 `const` 參考而暴露內部狀態。
24. 認為參考離開作用域會銷毀原物件。
25. 混淆函式內 `static` 與命名空間作用域 `static`。
26. 在標頭檔定義可修改全域變數。
27. 多個來源檔重複定義同一全域物件。
28. 混淆宣告與定義。
29. 混淆作用域、儲存期與連結。
30. 在尚未學習完整資源管理前手動建立長生命週期動態狀態。

# Part AH：Mermaid 流程圖

## Section CIII. 作用域與生命週期流程圖

### 1. 區塊作用域

```mermaid
flowchart TD
    A[進入區塊] --> B[執行到變數宣告]
    B --> C[名稱進入作用域並初始化物件]
    C --> D[在區塊內使用]
    D --> E[離開區塊]
    E --> F[名稱不可見]
    E --> G[自動物件被銷毀]
```

### 2. 作用域與生命週期

```mermaid
flowchart TD
    A[分析變數] --> B[找名稱可見範圍]
    A --> C[找物件建立時間]
    A --> D[找物件銷毀時間]
    B --> E[得到作用域]
    C --> F[得到生命週期起點]
    D --> G[得到生命週期終點]
```

### 3. 變數遮蔽

```mermaid
flowchart TD
    A[外層名稱 value] --> B[進入內層區塊]
    B --> C{內層宣告同名 value 嗎}
    C -- 是 --> D[內層名稱遮蔽外層名稱]
    C -- 否 --> E[繼續使用外層名稱]
    D --> F[離開內層區塊]
    F --> G[外層名稱再次可見]
```

### 4. 自動與靜態區域變數

```mermaid
flowchart TD
    A[呼叫函式] --> B{區域變數是否 static}
    B -- 否 --> C[每次呼叫建立新物件]
    C --> D[函式結束時銷毀]
    B -- 是 --> E[第一次到達時初始化]
    E --> F[後續呼叫保留原值]
    F --> G[程式結束時銷毀]
```

### 5. 回傳參考安全檢查

```mermaid
flowchart TD
    A[準備回傳參考] --> B{來源物件在函式結束後仍存在嗎}
    B -- 否 --> C[形成懸空參考]
    B -- 是 --> D{呼叫者需要修改嗎}
    D -- 是 --> E[可考慮回傳 T&]
    D -- 否 --> F[可回傳 const T& 或值]
```

### 6. 暫時物件

```mermaid
flowchart TD
    A[表示式產生暫時物件] --> B{直接綁定區域 const 參考嗎}
    B -- 是 --> C[生命週期通常延長到參考作用域結束]
    B -- 否 --> D[通常到完整表示式結束]
    C --> E[離開參考作用域後銷毀]
    D --> F[分號等完整表示式結尾後銷毀]
```

### 7. 名稱查找

```mermaid
flowchart TD
    A[使用名稱 value] --> B[從最內層作用域尋找]
    B --> C{找到宣告嗎}
    C -- 是 --> D[使用該名稱]
    C -- 否 --> E[往外層作用域尋找]
    E --> C
```

### 8. 三個概念

```mermaid
flowchart TD
    A[分析程式中的名稱與物件] --> B[Scope 名稱在哪裡可用]
    A --> C[Storage duration 物件存在多久]
    A --> D[Linkage 不同宣告是否代表同一實體]
```
