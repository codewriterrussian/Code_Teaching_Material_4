![Lesson 31 → Lesson 32 過渡圖](images/lesson_32/CPP_Lesson_32_img00_class_to_project.png)


> 這堂課的重點：把單一 `.cpp` 程式整理成可維護的多檔案 C++ 專案，理解 preprocessor、compiler、assembler、linker 的工作，正確分離宣告與定義，並建立可以重複執行的建置與測試流程。

> 本章以 C++17、Clang/GCC、Make 與 CMake 為主要工具。Visual Studio、Ninja、Meson、Bazel、套件管理器、GitHub Actions 與大型測試框架只做概念延伸。你不需要一開始就使用最複雜的工具，但專案必須能夠「乾淨建置、清楚分層、容易測試、容易找錯」。

## Section II. 今天的學習方式

1. 每個 `.cpp` 應該能說明：
   ```text
   我實作哪個模組？
   我 include 哪個自己的 header？
   我需要哪些標準函式庫？
   ```
2. Header 放公開宣告，source 放一般實作。
3. 不依賴其他 header 幫你間接 include。
4. 每次建置先分辨錯誤階段：
   ```text
   Preprocess → Compile → Link → Run → Test
   ```
5. 自己的程式使用嚴格 warnings。
6. Debug build 開啟 `-g` 與 sanitizer。
7. Release build 不代表可以忽略測試。
8. 每個 bug 修正最好加入 regression test。
9. Build 與 test 命令必須可重複執行。
10. 所有完整 C++ 範例使用 C++17 嚴格選項檢查。

# Part C：Translation Unit

![Translation Unit 是什麼？](images/lesson_32/CPP_Lesson_32_img08_translation_unit.png)


## Section XII. 什麼是 Translation Unit？

每個 `.cpp` 經過 preprocessor 展開後，形成一個 translation unit。

```text
main.cpp + 它 include 的 header
```

是一個 translation unit。

```text
calculator.cpp + 它 include 的 header
```

是另一個 translation unit。

## Section XXXI. 完整 Forward Declaration 範例

```cpp
// VALIDATE
#include <iostream>
#include <string>
using namespace std;

class Database;

class Service {
public:
    explicit Service(
        Database& initialDatabase
    )
        : database(
              initialDatabase
          ) {
    }

    string load() const;

private:
    Database& database;
};

class Database {
public:
    string query() const {
        return "data";
    }
};

string Service::load() const {
    return database.query();
}

int main() {
    Database database;
    Service service(database);

    cout << service.load()
         << '\n';

    return 0;
}
```

## Section LXII. 完整 Test Runner

```cpp
// VALIDATE
#include <iostream>
#include <string>
using namespace std;

class TestRunner {
public:
    void expectEqual(
        int actual,
        int expected,
        const string& name
    ) {
        ++totalCount;

        if (
            actual ==
            expected
        ) {
            cout << "PASS: "
                 << name
                 << '\n';

            return;
        }

        ++failedCount;

        cerr << "FAIL: "
             << name
             << " expected "
             << expected
             << " but got "
             << actual
             << '\n';
    }

    int result() const {
        cout << totalCount
             << " tests, "
             << failedCount
             << " failures\n";

        if (
            failedCount ==
            0
        ) {
            return 0;
        }

        return 1;
    }

private:
    int totalCount = 0;
    int failedCount = 0;
};

int multiply(
    int first,
    int second
) {
    return
        first *
        second;
}

int main() {
    TestRunner tests;

    tests.expectEqual(
        multiply(
            3,
            4
        ),
        12,
        "multiply positive"
    );

    tests.expectEqual(
        multiply(
            0,
            999
        ),
        0,
        "multiply by zero"
    );

    return tests.result();
}
```

```cpp
namespace score {

double average(
    const std::vector<int>& values
) {
    if (values.empty()) {
        throw std::invalid_argument(
            "values cannot be empty"
        );
    }

    const int total =
        std::accumulate(
            values.cbegin(),
            values.cend(),
            0
        );

    return
        static_cast<double>(
            total
        ) /
        static_cast<double>(
            values.size()
        );
}

}  // namespace score
```

# Part AK：快速概念檢查

## Section XCVI. 選擇題與簡答

### Q1. Header 主要放什麼？

<details><summary>查看答案</summary>

公開宣告、類別定義、模板定義、inline／constexpr 等可安全放入多個 translation unit 的內容。

</details>

### Q2. Source 主要放什麼？

<details><summary>查看答案</summary>

一般函式與類別成員的實作，以及只屬於該 translation unit 的 helper。

</details>

### Q3. Translation unit 是什麼？

<details><summary>查看答案</summary>

一個 source file 經 preprocessor 展開所有 include 後，交給 compiler 的完整單位。

</details>

### Q4. `-c` 有什麼作用？

<details><summary>查看答案</summary>

編譯成 object file，但不進行最後連結。

</details>

### Q5. Undefined reference 屬於哪個階段？

<details><summary>查看答案</summary>

通常是 linker 階段。

</details>

### Q6. Include guard 解決什麼？

<details><summary>查看答案</summary>

避免同一 header 在同一 translation unit 被重複展開。

</details>

### Q7. Header 中可以寫 `using namespace std;` 嗎？

<details><summary>查看答案</summary>

不建議，會污染所有 include 該 header 的程式。

</details>

### Q8. 為什麼 source 先 include 自己的 header？

<details><summary>查看答案</summary>

可及早確認 header 自己包含了所有必要依賴，並確保宣告與實作一致。

</details>

### Q9. Forward declaration 適合什麼情況？

<details><summary>查看答案</summary>

Header 只需要某型別的 pointer 或 reference，而不需要知道完整大小與成員時。

</details>

### Q10. Makefile 的 target、prerequisite、recipe 分別是什麼？

<details><summary>查看答案</summary>

Target 是要建立的結果，prerequisite 是依賴，recipe 是建立命令。

</details>

### Q11. `-MMD -MP` 有什麼用途？

<details><summary>查看答案</summary>

產生 header dependency files，讓 header 修改時相關 object file 重新編譯。

</details>

### Q12. CMake 的 `PUBLIC` include directory 代表什麼？

<details><summary>查看答案</summary>

目前 target 與連結它的使用者 target 都需要該 include path。

</details>

### Q13. Unit test 與 integration test 差異？

<details><summary>查看答案</summary>

Unit test 測試小型單位，integration test 測試多個模組的合作。

</details>

### Q14. 測試程式成功應回傳什麼？

<details><summary>查看答案</summary>

通常回傳 0；失敗回傳非 0。

</details>

### Q15. 為什麼浮點數不直接比較相等？

<details><summary>查看答案</summary>

二進位浮點表示與運算可能產生微小誤差，應使用 tolerance。

</details>

### Q16. Coverage 高是否代表測試品質一定高？

<details><summary>查看答案</summary>

不代表。Coverage 只表示程式被執行的範圍，不保證 assertion 正確或情境完整。

</details>

### Q17. Sanitizer 用途？

<details><summary>查看答案</summary>

在執行測試時協助發現記憶體錯誤與未定義行為。

</details>

### Q18. 為什麼不要 include `.cpp`？

<details><summary>查看答案</summary>

會破壞獨立編譯並容易造成重複定義；應 include header，再分別編譯與連結 source。

</details>

### Q19. Out-of-source build 是什麼？

<details><summary>查看答案</summary>

將建置產物放在獨立 `build/`，不污染 source tree。

</details>

### Q20. Regression test 是什麼？

<details><summary>查看答案</summary>

針對已修正 bug 加入測試，防止未來再次出現。

</details>

```cpp
    Database database;
```

<details><summary>查看答案</summary>

```cpp
    Database* database;
```

```cpp
    return 1;
```

放在 `.cpp`。

<details><summary>查看答案</summary>

Helper 具有 translation-unit-local internal linkage。

# Part AO：常見錯誤提醒

## Section C. 常見錯誤

1. 所有程式永遠放在單一 `.cpp`。
2. Header 與 source 宣告不一致。
3. Header 缺少 include guard。
4. Header 中使用 `using namespace std;`。
5. Header 依賴其他檔案間接 include。
6. Source 沒有先 include 自己的 header。
7. Header 放一般 global variable definition。
8. Header 放非 inline function definition。
9. 直接 include `.cpp`。
10. Circular include 未使用 forward declaration。
11. By-value incomplete type。
12. Function declaration namespace 與 definition namespace 不同。
13. Object file 沒有加入 link。
14. 同一 source 被加入 target 兩次。
15. 看到 linker error 卻只修改語法。
16. 忽略第一個 compiler diagnostic。
17. 關閉 warnings 代替修正程式。
18. 對第三方 code 全域使用 Werror。
19. Debug 與 release 使用不同必要邏輯。
20. 必要 validation 只寫在 assert。
21. Sanitizer build 使用過高 optimization 而難以追蹤。
22. Makefile recipe 使用空格代替 tab。
23. Makefile 沒追蹤 header dependency。
24. 將 build artifacts 提交到 Git。
25. CMake 使用全域設定污染所有 target。
26. 測試只有 `cout`，沒有 assertion 與 exit code。
27. 測試依賴其他測試先執行。
28. 浮點數直接比較完全相等。
29. 測試使用真實網路與固定使用者路徑。
30. Bug 修正後沒有 regression test。

# Part AP：Mermaid 流程圖

## Section CI. 專案組織、編譯與測試流程圖

### 1. C++ Build Pipeline

```mermaid
flowchart TD
    A[Source and Headers] --> B[Preprocessor]
    B --> C[Translation Unit]
    C --> D[Compiler]
    D --> E[Assembly]
    E --> F[Assembler]
    F --> G[Object Files]
    G --> H[Linker]
    H --> I[Executable or Library]
```

### 2. Error Stage

```mermaid
flowchart TD
    A[Build failed] --> B{Syntax or type diagnostic}
    B -- Yes --> C[Compile error]
    B -- No --> D{Undefined or duplicate symbol}
    D -- Yes --> E[Linker error]
    D -- No --> F{Program starts then fails}
    F -- Yes --> G[Runtime error]
    F -- No --> H[Test assertion failure]
```

### 3. Header Dependency

```mermaid
flowchart TD
    A[Header uses a type] --> B{Needs complete size or members}
    B -- Yes --> C[Include full header]
    B -- No --> D{Only pointer or reference}
    D -- Yes --> E[Forward declaration]
    D -- No --> C
```

### 4. Incremental Build

```mermaid
flowchart TD
    A[Source or Header changed] --> B[Dependency graph checks affected objects]
    B --> C[Recompile affected translation units]
    C --> D[Reuse unchanged object files]
    D --> E[Relink target]
```

### 5. Test Workflow

```mermaid
flowchart TD
    A[Arrange] --> B[Act]
    B --> C[Assert]
    C --> D{Pass}
    D -- Yes --> E[Record success]
    D -- No --> F[Print expected and actual]
    F --> G[Return nonzero exit code]
```

### 6. CMake Target Design

```mermaid
flowchart TD
    A[Domain source] --> B[Library target]
    B --> C[Application target]
    B --> D[Test target]
    C --> E[Executable]
    D --> F[CTest]
```

### 7. Bug Fix Workflow

```mermaid
flowchart TD
    A[Bug report] --> B[Create failing regression test]
    B --> C[Confirm test fails]
    C --> D[Fix implementation]
    D --> E[Run all tests]
    E --> F[Run sanitizer]
    F --> G[Commit fix and test]
```

### 8. CI Pipeline

```mermaid
flowchart TD
    A[Push or Pull Request] --> B[Configure]
    B --> C[Build]
    C --> D[Unit and Integration Tests]
    D --> E[Sanitizer]
    E --> F[Static Analysis]
    F --> G{All passed}
    G -- Yes --> H[Ready to merge]
    G -- No --> I[Block and report]
```
