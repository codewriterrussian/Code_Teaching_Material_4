## Section IV. 症狀不一定是根因

程式在：

```cpp
cout << values[index];
```

發生 crash，真正原因可能是：

- `index` 在更早之前被算錯。
- Vector 已被清空。
- Iterator 已失效。
- Memory 已被其他程式碼破壞。
- Reference 指向已銷毀物件。

不要只問：

```text
哪一行 crash？
```

還要問：

```text
錯誤狀態最早在哪裡產生？
```

## Section VI. 完整最小案例

```cpp
// VALIDATE
#include <iostream>
#include <vector>
using namespace std;

int sumPositive(
    const vector<int>& values
) {
    int total = 0;

    for (int value : values) {
        if (value > 0) {
            total += value;
        }
    }

    return total;
}

int main() {
    const vector<int> input{
        -1,
        2,
        3
    };

    const int actual =
        sumPositive(input);

    const int expected = 5;

    if (
        actual !=
        expected
    ) {
        cerr << "Expected "
             << expected
             << " but got "
             << actual
             << '\n';

        return 1;
    }

    cout << "Pass\n";

    return 0;
}
```

## Section XXI. 安全邊界範例

```cpp
// VALIDATE
#include <cstddef>
#include <iostream>
#include <stdexcept>
#include <vector>
using namespace std;

int readValue(
    const vector<int>& values,
    size_t index
) {
    if (
        index >=
        values.size()
    ) {
        throw out_of_range(
            "index is outside the vector"
        );
    }

    return values[index];
}

int main() {
    const vector<int> values{
        10,
        20,
        30
    };

    try {
        cout << readValue(
                    values,
                    3
                )
             << '\n';
    } catch (
        const out_of_range& error
    ) {
        cerr << error.what()
             << '\n';
    }

    return 0;
}
```

## Section XXIII. 安全整數加法

```cpp
// VALIDATE
#include <iostream>
#include <limits>
#include <stdexcept>
using namespace std;

int safeAdd(
    int first,
    int second
) {
    if (
        second > 0 &&
        first >
            numeric_limits<int>::max() -
                second
    ) {
        throw overflow_error(
            "positive integer overflow"
        );
    }

    if (
        second < 0 &&
        first <
            numeric_limits<int>::min() -
                second
    ) {
        throw overflow_error(
            "negative integer overflow"
        );
    }

    return
        first +
        second;
}

int main() {
    try {
        cout << safeAdd(
                    100,
                    200
                )
             << '\n';
    } catch (
        const overflow_error& error
    ) {
        cerr << error.what()
             << '\n';
    }

    return 0;
}
```

## Section XXVII. 完整 Invariant Check

![Assertion vs Runtime Validation](../images/lesson_33/CPP_Lesson_33_img41_assert_vs_runtime_validation.png)


```cpp
// VALIDATE
#include <cassert>
#include <iostream>
using namespace std;

class Counter {
public:
    void increment() {
        ++value;
        assertInvariant();
    }

    int get() const {
        assertInvariant();
        return value;
    }

private:
    void assertInvariant() const {
        assert(
            value >= 0
        );
    }

    int value = 0;
};

int main() {
    Counter counter;
    counter.increment();

    cout << counter.get()
         << '\n';

    return 0;
}
```

`assert()` 適合檢查程式內部假設，不適合處理使用者輸入、檔案不存在或網路失敗。

## Section XXIX. 完整簡易 Logger

```cpp
// VALIDATE
#include <iostream>
#include <string>
using namespace std;

enum class LogLevel {
    debug,
    info,
    warning,
    error
};

const char* toText(
    LogLevel level
) {
    switch (level) {
    case LogLevel::debug:
        return "DEBUG";
    case LogLevel::info:
        return "INFO";
    case LogLevel::warning:
        return "WARNING";
    case LogLevel::error:
        return "ERROR";
    }

    return "UNKNOWN";
}

void log(
    LogLevel level,
    const string& module,
    const string& message
) {
    cerr << "["
         << toText(level)
         << "] ["
         << module
         << "] "
         << message
         << '\n';
}

int main() {
    const int expected = 10;
    const int actual = 8;

    log(
        LogLevel::error,
        "score",
        "expected=" +
            to_string(expected) +
            " actual=" +
            to_string(actual)
    );

    return 0;
}
```

## Section XXXII. 完整 Regression Test

![Maximum 初始化 Bug](../images/lesson_33/CPP_Lesson_33_img46_maximum_initialization_bug.png)


```cpp
// VALIDATE
#include <iostream>
#include <vector>
using namespace std;

int maximumOrZero(
    const vector<int>& values
) {
    if (values.empty()) {
        return 0;
    }

    int maximum =
        values.front();

    for (int value : values) {
        if (value > maximum) {
            maximum = value;
        }
    }

    return maximum;
}

int main() {
    const int actual =
        maximumOrZero(
            {
                -5,
                -2,
                -10
            }
        );

    const int expected = -2;

    if (
        actual !=
        expected
    ) {
        cerr << "Regression failed: "
             << "expected "
             << expected
             << " but got "
             << actual
             << '\n';

        return 1;
    }

    cout << "Regression passed\n";

    return 0;
}
```

這可防止「maximum 初始化為 0」的舊 bug 再次出現。

## Section XXXVIII. 完整 `std::chrono` Benchmark

![`steady_clock` vs `system_clock`](../images/lesson_33/CPP_Lesson_33_img55_steady_clock_vs_system_clock.png)


```cpp
// VALIDATE
#include <chrono>
#include <cstddef>
#include <iostream>
#include <numeric>
#include <vector>
using namespace std;

long long sumValues(
    const vector<int>& values
) {
    return accumulate(
        values.cbegin(),
        values.cend(),
        0LL
    );
}

int main() {
    constexpr size_t count =
        100000;

    vector<int> values(
        count,
        1
    );

    constexpr int repetitions =
        100;

    long long result = 0;

    const auto start =
        chrono::steady_clock::now();

    for (
        int index = 0;
        index < repetitions;
        ++index
    ) {
        result +=
            sumValues(values);
    }

    const auto end =
        chrono::steady_clock::now();

    const auto elapsed =
        chrono::duration_cast<
            chrono::microseconds
        >(
            end -
            start
        );

    cout << "result="
         << result
         << " elapsed_us="
         << elapsed.count()
         << '\n';

    return 0;
}
```

保留並輸出 `result`，可降低整段計算被 optimizer 完全移除的可能性。

## Section XLIV. 第二大的不同數值

需要處理：

- 空輸入
- 只有一個值
- 所有值相同
- 最大值重複
- 負數

```cpp
// VALIDATE
#include <iostream>
#include <optional>
#include <set>
#include <vector>
using namespace std;

optional<int>
secondLargestDistinct(
    const vector<int>& values
) {
    set<int> distinct(
        values.cbegin(),
        values.cend()
    );

    if (
        distinct.size() <
        2
    ) {
        return nullopt;
    }

    auto iterator =
        distinct.rbegin();

    ++iterator;

    return *iterator;
}

bool expectEqual(
    const optional<int>& actual,
    const optional<int>& expected,
    const char* name
) {
    if (
        actual ==
        expected
    ) {
        cout << "PASS: "
             << name
             << '\n';

        return true;
    }

    cerr << "FAIL: "
         << name
         << '\n';

    return false;
}

int main() {
    bool success = true;

    success =
        expectEqual(
            secondLargestDistinct(
                {
                    5,
                    3,
                    5,
                    4
                }
            ),
            4,
            "duplicates"
        ) &&
        success;

    success =
        expectEqual(
            secondLargestDistinct(
                {
                    -1,
                    -5,
                    -3
                }
            ),
            -3,
            "negative values"
        ) &&
        success;

    success =
        expectEqual(
            secondLargestDistinct(
                {
                    7,
                    7
                }
            ),
            nullopt,
            "no second distinct"
        ) &&
        success;

    return
        success
            ? 0
            : 1;
}
```

Linker error。

<details><summary>查看答案</summary>

Breakpoint 在執行到指定位置時停下；watchpoint 在指定資料被修改時停下。

<details><summary>查看答案</summary>

<details><summary>查看答案</summary>

模組、操作、關鍵識別資訊、實際值、預期值與錯誤上下文。

</details>

<details><summary>查看答案</summary>

針對已修正 bug 建立的測試，用來防止同一錯誤再次出現。

</details>

### Q13. 為什麼先測量再優化？

<details><summary>查看答案</summary>

避免優化非瓶頸，並能證明修改是否真的改善效能。

找出程式時間或資源主要消耗在哪些函式與路徑。

# Part AE：常見錯誤提醒

## Section L. 常見錯誤

1. 沒有先重現就開始修改。
2. 一次修改多個不相關部分。
3. 只看 crash 行，不找錯誤狀態來源。
4. 忽略第一個 compiler error。
5. 關閉 warning 代替修正。
6. 把 linker error 當成語法錯誤。
7. Debug build 沒有 `-g`。
8. 高 optimization 下期待所有變數可查看。
9. Breakpoint 設在不會執行的 source line。
10. `step` 進入大量標準函式庫後迷失。
11. 不查看 call stack。
12. Watchpoint 設在已銷毀變數。
13. ASan 報錯後只在 crash 行加條件。
14. UBSan 報 signed overflow 卻忽略。
15. 用 assert 處理使用者錯誤。
16. Log 只寫 `"error"`。
17. Log 洩露 password 或 token。
18. Debug print 改變 timing 後誤認 bug 消失。
19. Bug 修正後沒有 regression test。
20. 只跑單一測試，不跑完整 suite。
21. 只測 Debug，不測 Release。
22. 只測 Release，不跑 sanitizer。
23. 沒有固定 random seed。
24. Benchmark 只執行一次。
25. Benchmark 混入大量 I/O。
26. Compiler 移除 benchmark 計算。
27. 優化非 hotspot。
28. 只看 Big-O，不測實際資料。
29. Core dump 與 executable 版本不一致。
30. Bug report 缺少輸入、環境與重現步驟。
