## Section II. 綜合專案的學習方式

1. 先寫需求，再寫 code。
2. 先完成最小可用版本 MVP。
3. 每個功能必須有清楚輸入與輸出。
4. Domain logic 不直接依賴 `cin`／`cout`。
5. Parser 接收 `istream&`。
6. Writer 接收 `ostream&`。
7. File I/O 放在獨立 repository。
8. `main()` 只負責組合與啟動。
9. 每完成一個功能就加入測試。
10. 每天結束前專案都應能 build。
11. 所有 warnings 必須處理。
12. Debug build 使用 sanitizer。
13. Commit 保持小型、可讀、可回復。
14. README 必須讓另一個人成功 build。
15. Demo 前重新 clone 並從零建置一次。

// VALIDATE
#include <iostream>
#include <stdexcept>
#include <string>
#include <utility>
using namespace std;

class Student {
public:
    Student(
        string initialId,
        string initialName,
        int initialScore
    )
        : idValue(
              std::move(
                  initialId
              )
          ),
          nameValue(
              std::move(
                  initialName
              )
          ),
          scoreValue(
              initialScore
          ) {
        validate();
    }

    const string& id() const noexcept {
        return idValue;
    }

    const string& name() const noexcept {
        return nameValue;
    }

    int score() const noexcept {
        return scoreValue;
    }

    void setScore(int newScore) {
        scoreValue =
            newScore;

        validate();
    }

private:
    void validate() const {
        if (idValue.empty()) {
            throw invalid_argument(
                "student id cannot be empty"
            );
        }

        if (nameValue.empty()) {
            throw invalid_argument(
                "student name cannot be empty"
            );
        }

        if (
            scoreValue < 0 ||
            scoreValue > 100
        ) {
            throw out_of_range(
                "student score must be 0 to 100"
            );
        }
    }

    string idValue;
    string nameValue;
    int scoreValue;
};

int main() {
    try {
        Student student(
            "S001",
            "Amy",
            95
        );

        cout << student.id()
             << " "
             << student.name()
             << " "
             << student.score()
             << '\n';
    } catch (
        const exception& error
    ) {
        cerr << error.what()
             << '\n';

        return 1;
    }

    return 0;
}

## Section XIX. 完整 Student Service

```cpp
// VALIDATE
#include <algorithm>
#include <iostream>
#include <optional>
#include <stdexcept>
#include <string>
#include <utility>
#include <vector>
using namespace std;

struct Student {
    string id;
    string name;
    int score;
};

class StudentService {
public:
    void add(Student student) {
        if (
            findById(
                student.id
            )
        ) {
            throw invalid_argument(
                "duplicate student id"
            );
        }

        if (
            student.id.empty() ||
            student.name.empty()
        ) {
            throw invalid_argument(
                "id and name are required"
            );
        }

        if (
            student.score < 0 ||
            student.score > 100
        ) {
            throw out_of_range(
                "score must be 0 to 100"
            );
        }

        students.push_back(
            std::move(
                student
            )
        );
    }

    optional<Student> findById(
        const string& id
    ) const {
        const auto iterator =
            find_if(
                students.cbegin(),
                students.cend(),
                [&id](
                    const Student& student
                ) {
                    return
                        student.id ==
                        id;
                }
            );

        if (
            iterator ==
            students.cend()
        ) {
            return nullopt;
        }

        return *iterator;
    }

    bool updateScore(
        const string& id,
        int newScore
    ) {
        if (
            newScore < 0 ||
            newScore > 100
        ) {
            throw out_of_range(
                "score must be 0 to 100"
            );
        }

        const auto iterator =
            find_if(
                students.begin(),
                students.end(),
                [&id](
                    const Student& student
                ) {
                    return
                        student.id ==
                        id;
                }
            );

        if (
            iterator ==
            students.end()
        ) {
            return false;
        }

        iterator->score =
            newScore;

        return true;
    }

    bool erase(
        const string& id
    ) {
        const auto oldSize =
            students.size();

        students.erase(
            remove_if(
                students.begin(),
                students.end(),
                [&id](
                    const Student& student
                ) {
                    return
                        student.id ==
                        id;
                }
            ),
            students.end()
        );

        return
            students.size() !=
            oldSize;
    }

    vector<Student>
    sortedByScoreDescending() const {
        vector<Student> result =
            students;

        sort(
            result.begin(),
            result.end(),
            [](
                const Student& first,
                const Student& second
            ) {
                if (
                    first.score !=
                    second.score
                ) {
                    return
                        first.score >
                        second.score;
                }

                return
                    first.id <
                    second.id;
            }
        );

        return result;
    }

    double averageScore() const {
        if (students.empty()) {
            return 0.0;
        }

        long long total = 0;

        for (
            const Student& student :
            students
        ) {
            total +=
                student.score;
        }

        return
            static_cast<double>(
                total
            ) /
            static_cast<double>(
                students.size()
            );
    }

    const vector<Student>&
    all() const noexcept {
        return students;
    }

private:
    vector<Student> students;
};

int main() {
    StudentService service;

    service.add(
        {
            "S001",
            "Amy",
            95
        }
    );

    service.add(
        {
            "S002",
            "Brian",
            88
        }
    );

    service.updateScore(
        "S002",
        91
    );

    const auto result =
        service.sortedByScoreDescending();

    for (
        const Student& student :
        result
    ) {
        cout << student.id
             << " "
             << student.score
             << '\n';
    }

    cout << service.averageScore()
         << '\n';

    return 0;
}
```

## Section XXII. 完整 CSV Round Trip

![Invalid File Row](../images/lesson_35/CPP_Lesson_35_img29_file_error_context.png)


```cpp
// VALIDATE
#include <iostream>
#include <sstream>
#include <stdexcept>
#include <string>
using namespace std;

struct Student {
    string id;
    string name;
    int score;
};

Student parseStudentLine(
    const string& line
) {
    istringstream input(line);

    Student student;
    string scoreText;

    if (
        !getline(
            input,
            student.id,
            ','
        ) ||
        !getline(
            input,
            student.name,
            ','
        ) ||
        !getline(
            input,
            scoreText
        )
    ) {
        throw runtime_error(
            "invalid student row"
        );
    }

    size_t processed = 0;

    student.score =
        stoi(
            scoreText,
            &processed
        );

    if (
        processed !=
        scoreText.size()
    ) {
        throw runtime_error(
            "invalid score field"
        );
    }

    if (
        student.id.empty() ||
        student.name.empty() ||
        student.score < 0 ||
        student.score > 100
    ) {
        throw runtime_error(
            "invalid student values"
        );
    }

    return student;
}

void writeStudent(
    ostream& output,
    const Student& student
) {
    output << student.id
           << ","
           << student.name
           << ","
           << student.score
           << '\n';
}

int main() {
    const Student original{
        "S001",
        "Amy",
        95
    };

    ostringstream output;

    writeStudent(
        output,
        original
    );

    const Student loaded =
        parseStudentLine(
            output.str()
        );

    cout << loaded.id
         << " "
         << loaded.name
         << " "
         << loaded.score
         << '\n';

    return 0;
}
```

```cpp
// VALIDATE
#include <iostream>
#include <sstream>
#include <string>
using namespace std;

enum class CommandType {
    add,
    list,
    quit,
    invalid
};

struct Command {
    CommandType type =
        CommandType::invalid;

    string id;
    string name;
    int score = 0;
};

Command parseCommand(
    const string& line
) {
    istringstream input(line);

    string action;
    input >> action;

    if (action == "list") {
        return {
            CommandType::list,
            "",
            "",
            0
        };
    }

    if (action == "quit") {
        return {
            CommandType::quit,
            "",
            "",
            0
        };
    }

    if (action == "add") {
        Command command;
        command.type =
            CommandType::add;

        if (
            !(input >>
              command.id >>
              command.name >>
              command.score)
        ) {
            command.type =
                CommandType::invalid;
        }

        return command;
    }

    return {};
}

int main() {
    const Command command =
        parseCommand(
            "add S001 Amy 95"
        );

    if (
        command.type ==
        CommandType::add
    ) {
        cout << command.id
             << " "
             << command.name
             << " "
             << command.score
             << '\n';
    }

    return 0;
}
```

# Part L：完整小型應用程式範例

## Section XXXIII. Todo Service

```cpp
// VALIDATE
#include <algorithm>
#include <iostream>
#include <optional>
#include <stdexcept>
#include <string>
#include <utility>
#include <vector>
using namespace std;

struct Task {
    int id;
    string title;
    bool completed;
};

class TodoService {
public:
    int addTask(
        string title
    ) {
        if (title.empty()) {
            throw invalid_argument(
                "task title cannot be empty"
            );
        }

        const int id =
            nextId;

        ++nextId;

        tasks.push_back(
            {
                id,
                std::move(
                    title
                ),
                false
            }
        );

        return id;
    }

    bool completeTask(int id) {
        const auto iterator =
            find_if(
                tasks.begin(),
                tasks.end(),
                [id](
                    const Task& task
                ) {
                    return
                        task.id ==
                        id;
                }
            );

        if (
            iterator ==
            tasks.end()
        ) {
            return false;
        }

        iterator->completed =
            true;

        return true;
    }

    bool removeTask(int id) {
        const auto oldSize =
            tasks.size();

        tasks.erase(
            remove_if(
                tasks.begin(),
                tasks.end(),
                [id](
                    const Task& task
                ) {
                    return
                        task.id ==
                        id;
                }
            ),
            tasks.end()
        );

        return
            tasks.size() !=
            oldSize;
    }

    optional<Task> findTask(
        int id
    ) const {
        const auto iterator =
            find_if(
                tasks.cbegin(),
                tasks.cend(),
                [id](
                    const Task& task
                ) {
                    return
                        task.id ==
                        id;
                }
            );

        if (
            iterator ==
            tasks.cend()
        ) {
            return nullopt;
        }

        return *iterator;
    }

    vector<Task>
    activeTasks() const {
        vector<Task> result;

        copy_if(
            tasks.cbegin(),
            tasks.cend(),
            back_inserter(
                result
            ),
            [](
                const Task& task
            ) {
                return
                    !task.completed;
            }
        );

        return result;
    }

private:
    vector<Task> tasks;
    int nextId = 1;
};

int main() {
    TodoService service;

    const int firstId =
        service.addTask(
            "Write tests"
        );

    service.addTask(
        "Update README"
    );

    service.completeTask(
        firstId
    );

    for (
        const Task& task :
        service.activeTasks()
    ) {
        cout << task.id
             << " "
             << task.title
             << '\n';
    }

    return 0;
}
```

struct Student {
    string id;
    int score;
};

class StudentCollection {
public:
    void add(
        const Student& student
    ) {
        for (
            const Student& current :
            students
        ) {
            if (
                current.id ==
                student.id
            ) {
                throw invalid_argument(
                    "duplicate id"
                );
            }
        }

        students.push_back(
            student
        );
    }

    size_t size() const noexcept {
        return students.size();
    }

private:
    vector<Student> students;
};

        {

        }

            true;

        collection.size() !=

# Part AF：快速概念檢查

## Section LXXII. 選擇題與簡答

### Q1. 綜合專案第一步是什麼？

<details><summary>查看答案</summary>

先定義問題、使用者、需求與成功條件，不是先建立 class。

</details>

### Q2. MVP 是什麼？

<details><summary>查看答案</summary>

能提供核心價值的最小可用版本。

</details>

### Q3. Vertical slice 是什麼？

<details><summary>查看答案</summary>

從 UI 到 domain、repository 與 output 的一條完整可執行功能路徑。

</details>

### Q4. Domain logic 應直接使用 `cin`／`cout` 嗎？

<details><summary>查看答案</summary>

通常不應。輸入輸出應由 UI 層負責，domain logic 接收參數並回傳結果。

</details>

### Q5. Repository 的用途？

<details><summary>查看答案</summary>

抽象資料存取，讓 service 不必綁定特定檔案或資料來源。

</details>

### Q6. 為什麼 parser 接收 `istream&`？

<details><summary>查看答案</summary>

可同時處理檔案、標準輸入與 stringstream，也更容易測試。

</details>

### Q7. 為什麼 writer 接收 `ostream&`？

<details><summary>查看答案</summary>

可寫入檔案、cout 或 ostringstream，增加重用與可測試性。

</details>

### Q8. Save／load round-trip test 驗證什麼？

<details><summary>查看答案</summary>

資料儲存再載入後所有欄位與語意保持一致。

</details>

### Q9. 為什麼要使用 temporary file 安全儲存？

<details><summary>查看答案</summary>

避免直接覆寫時中途失敗，造成原資料損壞。

</details>

### Q10. Definition of Done 包含什麼？

<details><summary>查看答案</summary>

Implementation、validation、tests、warnings、sanitizer、documentation 與 commit 都完成。

</details>

### Q11. Unit test 與 integration test 差異？

<details><summary>查看答案</summary>

Unit test 測單一邏輯單位；integration test 測多個模組合作。

</details>

### Q12. 為什麼不應全部使用 shared_ptr？

<details><summary>查看答案</summary>

會隱藏 ownership、增加成本並可能形成 cycle；應先使用值或 unique ownership。

</details>

### Q13. God Object 是什麼？

<details><summary>查看答案</summary>

一個 class 負責過多功能、依賴大量模組且難以測試與修改。

</details>

### Q14. 為什麼要有小型 commit？

<details><summary>查看答案</summary>

容易 review、回復、找 bug，也能清楚表示每次修改意圖。

</details>

### Q15. README 最重要的功能？

<details><summary>查看答案</summary>

讓另一個人理解專案目的，並能成功 build、test 與 run。

</details>

### Q16. Demo 前為什麼要重新 clone？

<details><summary>查看答案</summary>

驗證專案不依賴本機未提交檔案、舊 build artifacts 或特殊環境。

</details>

### Q17. 何時需要 polymorphism？

<details><summary>查看答案</summary>

當多種實作需要共用 interface，而且呼叫端不應綁定實際型別時。

</details>

### Q18. 為什麼先完成 MVP 再擴充？

<details><summary>查看答案</summary>

降低整合風險，確保核心功能先可執行與可測試。

</details>

### Q19. Non-functional requirement 範例？

<details><summary>查看答案</summary>

C++17、零 warnings、有 tests、無 memory leak、效能與文件要求。

</details>

### Q20. 專案完成後還要做什麼？

<details><summary>查看答案</summary>

執行完整 tests、sanitizer、Release build、README 檢查與 demo rehearsal。

</details>

# Part AG：程式閱讀練習

## Section LXXIII. 判斷設計問題

### 題目 1

```cpp
void addStudent() {
    string id;
    cin >> id;

    students.push_back(...);

    cout << "done";
}
```

<details><summary>查看答案</summary>

UI、domain logic 與 storage 混在同一函式，難以測試。應把輸入解析與 service 操作分開。

</details>

### 題目 2

```cpp
class StudentService {
private:
    CsvRepository repository{
        "/Users/name/data.csv"
    };
};
```

<details><summary>查看答案</summary>

硬編碼 absolute path 且 service 綁定實作，難以測試與部署。應注入 repository 與 path。

</details>

### 題目 3

```cpp
ofstream output(
    path,
    ios::trunc
);
```

立刻覆寫正式資料。

<details><summary>查看答案</summary>

若中途失敗可能破壞原資料。重要資料應先寫 temporary file，再安全替換。

</details>

### 題目 4

```cpp
shared_ptr<Student> student =
    make_shared<Student>();
```

但只有一個 service 擁有 student。

<details><summary>查看答案</summary>

Shared ownership 可能不必要；可直接存值或使用 unique_ptr。

</details>

### 題目 5

```cpp
vector<Student> sorted =
    students;

sort(
    students.begin(),
    students.end(),
    ...
);
```

<details><summary>查看答案</summary>

建立 `sorted` 卻排序 `students`，可能是 logic bug。應確認是否要保留原順序並排序副本。

</details>

### 題目 6

```cpp
catch (...) {
}
```

<details><summary>查看答案</summary>

完全吞掉錯誤，使用者與 log 都看不到原因。應至少在適當邊界回報，並只捕捉能處理的錯誤。

</details>

### 題目 7

```cpp
bool save() {
    output << data;
    return true;
}
```

<details><summary>查看答案</summary>

沒有檢查開啟與寫入狀態，可能錯誤回報成功。

</details>

### 題目 8

```cpp
int main() {
    // 900 lines
}
```

<details><summary>查看答案</summary>

Main 承擔過多責任。應分離 parser、service、repository 與 UI functions。

</details>

### 題目 9

所有 tests 都使用同一個：

```text
data.csv
```

<details><summary>查看答案</summary>

測試可能互相污染並依賴執行順序。應使用獨立 temporary files。

</details>

### 題目 10

README 只有：

```text
run main.cpp
```

<details><summary>查看答案</summary>

缺少 compiler、CMake、build、test、run、commands 與資料格式說明。

</details>

### 題目 11

Commit：

```text
final version
```

包含 50 個功能。

<details><summary>查看答案</summary>

難以 review、回復與找 bug。應拆成小型、單一目的 commits。

</details>

### 題目 12

專案有 30 個 class，但 MVP 尚不能執行。

<details><summary>查看答案</summary>

可能過度設計。應先完成一條可運作 vertical slice。

</details>

# Part AJ：常見錯誤提醒

## Section LXXX. 常見錯誤

1. 沒有需求文件就開始寫 code。
2. MVP 尚未完成就增加大量功能。
3. `main()` 太大。
4. UI、domain 與 file I/O 混在一起。
5. Model 沒有 validation。
6. Duplicate ID policy 不清楚。
7. 使用 absolute path。
8. Parser 直接綁定檔案。
9. Repository 直接綁在 service 內。
10. 為簡單專案建立過多 abstraction。
11. 所有物件都使用 shared_ptr。
12. 用 inheritance 取代簡單 composition。
13. Catch all 後完全忽略錯誤。
14. Save 不檢查 stream state。
15. 直接 trunc 正式資料。
16. Load 遇到錯誤列仍靜默接受。
17. CSV parser 不驗證欄位數。
18. File format 沒有版本策略。
19. Tests 共用同一資料檔。
20. Tests 依賴執行順序。
21. 只有 happy-path tests。
22. 沒有 round-trip test。
23. 沒有 regression test。
24. Compiler warnings 未處理。
25. 沒有 sanitizer build。
26. README 無法讓別人成功建置。
27. Commit 太大且訊息不清楚。
28. Build artifacts 被提交。
29. Demo 前未重新 clone 測試。
30. 專案完成後仍無法說明設計決策。
