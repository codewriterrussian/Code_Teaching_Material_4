# Lesson 29：File Input and Output 檔案輸入輸出

<!-- Images inserted from C++_29.txt insertion plan. -->

![Lesson 28 → Lesson 29 過渡圖](images/lesson_29/CPP_Lesson_29_img00_exception_raii_to_file_io.png)
> 這堂課的重點：讓程式把資料寫入檔案，並在之後重新讀取。你會學習 `ifstream`、`ofstream`、`fstream`、文字與二進位檔案、開啟模式、格式化讀取、逐行讀取、串流狀態、檔案位置、RAII、自動關閉、`std::filesystem`，以及如何安全處理檔案錯誤。

> 本章以 C++17 為基準。檔案輸入輸出的核心仍是 stream：`cin` 從標準輸入讀取，`cout` 寫到標準輸出；檔案串流則把同樣的操作連接到檔案。JSON、XML、SQLite、壓縮檔、網路串流與完整序列化框架會留到其他專題。

## Section II. 今天的學習方式

1. 每個檔案操作先回答：
   ```text
   讀還是寫？
   文字還是二進位？
   覆寫還是附加？
   檔案不存在時怎麼辦？
   格式錯誤時怎麼辦？
   ```
2. 讀取迴圈優先：
   ```cpp
   while (file >> value)
   ```
   或：
   ```cpp
   while (getline(file, line))
   ```
3. 不使用：
   ```cpp
   while (!file.eof())
   ```
4. 檔案開啟後立即檢查狀態。
5. 重要寫入完成後再次檢查 stream。
6. 路徑使用：
   ```cpp
   filesystem::path
   ```
7. Parser 接收：
   ```cpp
   istream&
   ```
8. Writer 接收：
   ```cpp
   ostream&
   ```
9. 二進位格式要明確定義，不直接傾倒複雜物件記憶體。
10. 所有合法完整程式使用嚴格 C++17 選項檢查。

```cpp
#include <string>
```

```cpp
        "lesson29_values.txt";

    {
        ofstream output(path);

        if (!output) {
            return 1;
        }

        output << "Amy 95\n";
    }

    ifstream input(path);

    if (!input) {
        cerr << "Unable to open input file.\n";
        return 1;
```

## Section XVI. 完整混用範例

```cpp
// VALIDATE
#include <fstream>
#include <iostream>
#include <limits>
#include <string>
using namespace std;

int main() {
    const string path =
        "lesson29_mixed.txt";

    {
        ofstream output(path);

        if (!output) {
            return 1;
        }

        output << "2\n";
        output << "First full line\n";
        output << "Second full line\n";
    }

    ifstream input(path);

    if (!input) {
        return 1;
    }

    int count = 0;

    if (!(input >> count)) {
        return 1;
    }

    input.ignore(
        numeric_limits<
            streamsize
        >::max(),
        '\n'
    );

    for (
        int index = 0;
        index < count;
        ++index
    ) {
        string line;

        if (!getline(input, line)) {
            cerr << "Missing line.\n";
            return 1;
        }

        cout << line
             << '\n';
    }

    return 0;
}
```

```cpp
int main() {
```

## Section XX. 基本形式

```cpp
fstream file(
    path,
    ios::in |
        ios::out
);
```

若檔案不存在，實際建立行為取決於模式組合。

需要清楚設計檔案是否應預先存在。

---

## Section XXI. Get Pointer 與 Put Pointer

- Get pointer：下一次讀取位置。
- Put pointer：下一次寫入位置。

可分別使用：

```cpp
seekg()
seekp()
```

---

## Section XXII. 完整讀寫範例

```cpp
// VALIDATE
#include <fstream>
#include <iostream>
#include <string>
using namespace std;

int main() {
    const string path =
        "lesson29_read_write.txt";

    {
        ofstream createFile(path);

        if (!createFile) {
            return 1;
        }

        createFile << "ABCDE";
    }

    fstream file(
        path,
        ios::in |
            ios::out
    );

    if (!file) {
        return 1;
    }

    file.seekp(
        2,
        ios::beg
    );

    file.put('X');

    file.flush();

    file.seekg(
        0,
        ios::beg
    );

    string content;

    getline(
        file,
        content
    );

    cout << content
         << '\n';

    return 0;
}
```

輸出：

```text
ABXDE
```

## Section XXVII. 啟用例外

```cpp

    ios::badbit
);
```

指定狀態發生時會丟出：


## Section XXVIII. 使用時機

適合：

- 無法繼續時。
- 希望集中錯誤處理。
- API 已採用例外設計。

不適合：

- EOF 是正常流程。
- 每次解析失敗都要自行恢復。
- 呼叫端預期用狀態處理。

---

## Section XXIX. 完整 Exception Mask

```cpp
// VALIDATE
#include <fstream>
#include <iostream>
#include <ios>
#include <string>
using namespace std;

int main() {
    const string path =
        "lesson29_exception_mask.txt";

    {
        ofstream output(path);

        if (!output) {
            return 1;
        }

        output << "42\n";
    }

    try {
        ifstream input;

        input.exceptions(
            ios::failbit |
            ios::badbit
        );

        input.open(path);

        int value = 0;
        input >> value;

        cout << value
             << '\n';
    } catch (
        const ios_base::failure& error
    ) {
        cerr << error.what()
             << '\n';

        return 1;
    }

    return 0;
}
```

## Section XXXVI. 完整簡化 CSV 解析

```cpp
// VALIDATE
#include <iostream>
#include <sstream>
#include <stdexcept>
#include <string>
using namespace std;

struct Student {
    string name;
    int score;
};

Student parseStudentCsv(
    const string& line
) {
    istringstream input(line);

    Student student;
    string scoreText;

    if (
        !getline(
            input,
            student.name,
            ','
        ) ||
        !getline(
            input,
            scoreText
        )
    ) {
        throw runtime_error(
            "Invalid CSV row."
        );
    }

    size_t processed = 0;

    student.score =
        stoi(
            scoreText,
            &processed
        );

    if (
        processed !=
        scoreText.size()
    ) {
        throw runtime_error(
            "Invalid score field."
        );
    }

    return student;
}

int main() {
    try {
        Student student =
            parseStudentCsv(
                "Amy,95"
            );

        cout << student.name
             << " "
             << student.score
             << '\n';
    } catch (
        const exception& error
    ) {
        cerr << error.what()
             << '\n';

        return 1;
    }

    return 0;
}
```

```cpp
#include <fstream>
#include <iostream>
#include <string>
using namespace std;

int main() {
```

```cpp
        "lesson29_integer.bin";

            static_cast<
                streamsize
            >(
                sizeof(

                )
            )

            return 1;

            reinterpret_cast<
```

## Section LIX. 直接覆寫風險

```cpp

    path,
    ios::trunc
);
```

開啟成功時舊內容就可能被清除。

若後續寫入中途失敗，檔案可能只剩部分內容。

## Section LX. 暫存檔策略

1. 寫入同目錄的暫存檔。
2. 檢查所有寫入。
3. Flush 與 close。

5. Rename 暫存檔成正式檔。

---

## Section LXI. 完整簡化安全儲存

```cpp
// VALIDATE
#include <filesystem>
#include <fstream>
#include <iostream>
#include <string>
namespace fs = std::filesystem;
using namespace std;

bool saveTextSafely(
    const fs::path& target,
    const string& content
) {
    const fs::path temporary =
        target.string() +
        ".tmp";

    {
        ofstream output(
            temporary,
            ios::out |
                ios::trunc
        );

        if (!output) {
            return false;
        }

        output << content;
        output.flush();

        if (!output) {
            return false;
        }
    }

    error_code error;

    fs::remove(
        target,
        error
    );

    error.clear();

    fs::rename(
        temporary,
        target,
        error
    );

    if (error) {
        fs::remove(
            temporary,
            error
        );

        return false;
    }

    return true;
}

int main() {
    const fs::path path =
        "lesson29_safe_save.txt";

    cout << boolalpha
         << saveTextSafely(
                path,
                "Important content\n"
            )
         << '\n';

    return 0;
}
```

這是教學用簡化版本；生產環境還需考慮備份、權限與原子替換語意。

```cpp
#include <string>

bool appendLog(

    );

        cerr << "Unable to write log.\n";
        return 1;
    }

    cout << "Log written\n";

    return 0;
}
```

### Q1. `ifstream` 用來做什麼？

### Q4. 檔案串流一定要手動 `close()` 嗎？

<details><summary>查看答案</summary>

一般不一定需要；物件解構時會自動關閉。若需要立即檢查關閉結果、重新開啟或確定寫入完成，可明確關閉。

</details>

### Q5. 為什麼不應使用 `while (!file.eof())`？

<details><summary>查看答案</summary>

EOF 通常在一次讀取失敗後才設定，可能多處理一筆舊資料。應直接以讀取操作作為迴圈條件。

### Q6. `ios::app` 有什麼作用？

<details><summary>查看答案</summary>

讓每次寫入都發生在檔案尾端。

### Q7. `ios::trunc` 有什麼作用？

<details><summary>查看答案</summary>

### Q8. `getline()` 與 `operator>>` 的主要差異？

<details><summary>查看答案</summary>

`getline()` 讀取整行並保留行內空格；`operator>>` 進行格式化讀取，通常跳過前導空白並在空白處停止字串讀取。

<details><summary>查看答案</summary>

</details>

<details><summary>查看答案</summary>

格式化讀取或一般操作失敗，但不一定是嚴重底層錯誤。

</details>

### Q11. `badbit` 代表什麼？

<details><summary>查看答案</summary>

較嚴重的底層輸入輸出錯誤。

</details>

### Q12. `clear()` 會修復檔案內容嗎？

### Q13. `tellg()` 取得什麼？

<details><summary>查看答案</summary>

### Q14. `seekp()` 操作什麼？

寫入位置。

<details><summary>查看答案</summary>

### Q17. 相對路徑以什麼為基準？

程式執行時的 current working directory。

### Q18. 為什麼 parser 適合接收 `istream&`？

<details><summary>查看答案</summary>

<details><summary>查看答案</summary>

# Part AE：常見錯誤提醒

## Section LXXVI. 常見錯誤

1. 開啟檔案後不檢查狀態。
2. 寫入完成後不檢查狀態。
3. 使用 `while (!eof())`。
4. `>>` 後直接 `getline()` 而未處理換行。
5. 不理解 `ws` 會跳過所有前導空白。
6. 無意間使用 `ios::trunc` 清除檔案。
7. 需要附加卻使用預設 `ofstream`。
8. 混淆 `ios::app` 與 `ios::ate`。
9. 假設相對路徑以來源碼目錄為基準。
10. 假設 IDE 與終端工作目錄相同。
11. 手動拼接 `/` 或 `\` 而不用 `filesystem::path`。
12. 對不存在目錄直接開啟內部檔案。
13. Stream fail 後不 `clear()` 就繼續讀取。
14. Clear 狀態後沒有略過造成錯誤的 token。
15. 解參考或使用失敗讀取後的舊資料。
16. 把簡化逗號切割誤當完整 CSV parser。
17. 沒有驗證每列欄位數。
18. 錯誤訊息沒有行號。
19. 直接寫入含 `string` 的 struct 記憶體。
20. 直接寫入指標值。
21. 忽略二進位格式 endianness。
22. 忽略 struct padding 與版本變更。
23. 使用 `sizeof` 建立不具可攜性的檔案協定。
24. 讀取檔案提供的長度後無上限配置記憶體。
25. 依賴 directory iterator 原始順序。
26. 直接覆寫重要檔案且沒有暫存檔策略。
27. 日誌中寫入密碼或 token。
28. 多個程序同時寫檔卻沒有同步設計。
29. 按值傳遞不可複製的 stream。
30. Parser 直接綁定 `ifstream`，導致難以測試與重用。
