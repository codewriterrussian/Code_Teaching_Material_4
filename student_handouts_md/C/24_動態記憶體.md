> 這堂課的重點：從「輸入多少個整數事先不知道」的問題開始，理解固定大小陣列為什麼無法在執行期間直接變大。接著利用指標改指向不同陣列，觀察自動變數的生命週期及懸空指標問題，最後學習使用 `malloc()` 動態配置、使用 `free()` 釋放，以及使用 `realloc()` 重新配置記憶體。

## Section II. 今天的學習方式

1. 先畫固定大小陣列：
   ```text
   [ ][ ][ ][ ][ ]
   ```
2. 在陣列旁同時記錄：
   - `length`：目前有幾筆資料
   - `capacity`：最多可容納幾筆資料
3. 每次輸入後標記資料應放入哪一格。
4. 輸入數量達到容量時，先停止並分析原因。
5. 不把「陣列變大」理解為直接在舊陣列後方加格子。
6. 使用三個步驟理解手動擴充：
   ```text
   建立較大空間
   → 複製舊資料
   → 改用新空間
   ```
7. 再加入第四個必要步驟：
   ```text
   → 歸還舊空間
   ```
8. 每次遇到區域變數，都標出它所在的大括號。
9. 畫出自動變數：
   - 何時配置
   - 何時釋放
10. 指標箭頭仍指向某位置時，要確認該位置中的物件是否仍然存在。
11. 將「位址仍在指標裡」與「該位址仍可合法存取」分開判斷。
12. 使用 `malloc()` 時先計算元素數量，再乘上單一元素大小。
13. 不把 `int` 大小寫死成 `4`。
14. 每次配置後立即檢查是否為 `NULL`。
15. `malloc()` 得到的空間先視為未知內容，寫入後才能讀取。

    - 原地擴充

# Part A：固定大小陣列的限制

## Section IV. 輸入任意個整數後一起印出

### 1. 題目

讓使用者輸入任意個整數，輸入：

```text
0
```

時結束，再將先前所有整數一起印出。

例如：

```text
1
7
9
2
3
5
0
```

輸出：

```text
Numbers: 1 7 9 2 3 5
```

---

### 2. 先完成輸入迴圈

```c
while (1) {
    int input;

    if (scanf("%d", &input) != 1) {
        break;
    }

    if (input == 0) {
        break;
    }
}
```

這時每次輸入都只存在區域變數 `input` 中，下一次迴圈便會被新值取代，因此還沒有保存所有資料。

---

### 3. 需要陣列與長度

概念：

```c
int numbers[10];
int length = 0;
```

- `numbers` 保存輸入資料。
- `length` 保存目前已經輸入幾個整數。

新增：

```c
numbers[length] = input;
length++;
```

---

### 4. 固定大小版本

```c
#include <stdio.h>

int main(void) {
    int numbers[10];
    int length = 0;

    while (length < 10) {
        int input;

        if (scanf("%d", &input) != 1) {
            break;
        }

        if (input == 0) {
            break;
        }

        numbers[length] = input;
        length++;
    }

    printf("Numbers: ");

    for (int i = 0; i < length; i++) {
        printf("%d ", numbers[i]);
    }

    printf("\n");

    return 0;
}
```

---

### 5. 容量與長度

在上面的程式中：

```text
capacity = 10
length   = 目前已保存的數量
```

若只輸入六筆：

```text
length == 6
```

剩餘四格仍未作為有效資料使用。

### 6. 為什麼迴圈要加入 `length < 10`？

若只寫：

```c
while (1)
```

使用者輸入第十一個非零整數時，程式會嘗試寫入：

```c
numbers[10]
```

合法索引只有：

```text
0–9
```

超出範圍屬於未定義行為。

---

### 7. 固定容量版本仍不符合「任意個」

它最多只能保存十個整數。

若把容量改成一千，仍然只是把限制改成一千，並沒有真正解決數量未知的問題。

# Part B：為什麼陣列不能直接變大？

## Section V. 陣列建立後大小固定

### 8. 陣列大小在建立時決定

```c
int numbers[3] = {1, 2, 3};
```

這個陣列物件有三個元素。

不能在稍後直接變成四個元素。

---

### 9. 陣列元素需要連續配置

概念：

```text
numbers:
[1][2][3]
```

程式不能假設最後一格後面的記憶體一定沒有被其他物件使用。

因此不能直接宣告：

```text
請在原陣列後面再增加一格
```

### 10. 一般擴充方法

來源投影片整理成三步：

1. 產生一個較大的新陣列。
2. 將舊資料複製到新陣列。
3. 用新陣列取代舊陣列。

概念圖：

```text
舊陣列：[1][2][3]

新陣列：[1][2][3][ ]
```

---

### 11. 陣列不能整體賦值

錯誤概念：

```c
int numbers[3] = {1, 2, 3};
int larger[4];

numbers = larger;
```

陣列名稱不能放在整體賦值的左方。

---

## Section VI. 來源嘗試：可變長度陣列

### 12. 可變長度陣列

C99 支援以執行期間整數建立區域陣列：

```c
int larger[length + 1];
```

這稱為：

```text
Variable Length Array
可變長度陣列
```

它不允許長度為零。

---

### 13. VLA 仍不是原陣列變大

```c
int larger[length + 1];
```

建立的是一個新的陣列物件，而不是改變舊陣列。

仍需要將舊元素逐一複製：

```c
for (int i = 0; i < length; i++) {
    larger[i] = numbers[i];
}
```

---

### 14. VLA 的可攜性提醒

VLA 在 C99 中加入，C11 之後可由實作選擇是否支援。

因此即使語法能在某些 C17 編譯器使用，也不應把它當成所有環境都必定支援的動態陣列方案。

# Part C：同一個指標指向不同陣列

## Section VII. 指標可以改變所指位置

### 15. 以指標保存陣列第一個元素位址

```c
int first[1] = {1};
int *numbers = first;
```

此時：

```text
numbers → first[0]
```

---

### 16. 讓指標改指向另一個陣列

```c
int second[2] = {2, 3};

numbers = second;
```

現在：

```text
numbers → second[0]
```

同一個指標變數可以先後保存不同陣列的起始位址。

---

### 17. 完整合法示範

```c
#include <stdio.h>

int main(void) {
    int first[1] = {1};
    int second[2] = {2, 3};
    int *numbers = first;
    int length = 1;

    for (int i = 0; i < length; i++) {
        printf("%d ", numbers[i]);
    }

    printf("\n");

    numbers = second;
    length = 2;

    for (int i = 0; i < length; i++) {
        printf("%d ", numbers[i]);
    }

    printf("\n");

    return 0;
}
```

輸出：

```text
1
2 3
```

---

### 18. 指標可重新賦值，陣列名稱不行

合法：

```c
numbers = second;
```

不合法：

```c
first = second;
```

指標是保存位址的普通變數；陣列名稱不是可重新指向的指標變數。

### 19. 指標改指向不等於保存原陣列

當：

```c
numbers = second;
```

之後，`numbers` 不再保存 `first` 的位址。

如果沒有其他方式保存第一個動態配置位址，可能造成記憶體洩漏。

若 `first` 是自動陣列，它仍按照自己的生命週期存在或消失，不受 `numbers` 決定。

# Part D：變數的生命週期

## Section VIII. 每個變數需要專屬記憶體

### 20. 物件需要記憶體空間

例如：

```c
int number;
```

需要可保存一個 `int` 的空間。

```c
int values[10];
```

需要可保存十個 `int` 的連續空間。

可以使用：

```c
sizeof(number)
sizeof(values)
```

查詢所需位元組數。

---

### 21. 專屬空間的意思

當物件的生命週期仍在持續時，該空間不能被另一個同時存在的物件任意佔用。

記憶體有限，因此物件生命週期結束後，空間需要能被後續物件重新使用。

---

## Section IX. 自動變數的生命週期

### 22. 一般區域變數通常是自動變數

```c
{
    int number;

    /* number 在這個區塊中存在 */
}
```

來源投影片的簡化模型：

- 執行進入變數所在區塊時，配置記憶體。
- 執行離開該區塊時，釋放記憶體。

---

### 23. 可視範圍與生命週期

在區塊外：

```text
不能再使用 number 這個名稱
```

同時，該自動物件的生命週期也已結束。

要分辨：

- scope：名稱可在哪些程式碼中使用。
- lifetime：物件在執行期間是否仍然存在。

---

### 24. VLA 位於迴圈區塊中

來源問題程式的核心：

```c
while (1) {
    int larger[length + 1];

    /* 複製資料 */

    numbers = larger;
}
```

`larger` 是迴圈區塊中的自動陣列。

---

### 25. 到達右大括號時發生什麼？

```c
}
```

表示離開本次迴圈區塊。

`larger` 的生命週期結束，其儲存空間可以被後續程式重新利用。

---

### 26. 指標仍保存舊位址

即使：

```c
numbers = larger;
```

將 `larger` 的起始位址保存到 `numbers`，也不會改變 `larger` 的生命週期。

離開區塊後：

```text
numbers 中仍有一個位址值
但該位址不再指向仍存在的 larger 物件
```

這稱為：

```text
懸空指標
dangling pointer
```

### 27. 透過懸空指標存取

例如後續使用：

```c
numbers[i]
```

會存取生命週期已結束的空間，屬於未定義行為。

可能表現為：

- 看似仍有舊資料
- 資料突然改變
- 程式崩潰
- 不同最佳化設定出現不同結果

不能依賴任何結果。

---

### 28. 重要結論

> 指標只保存位址，不能控制被指向物件的生命週期。

這正是需要動態配置記憶體的主要原因之一：讓配置空間的生命週期由程式明確控制，而不是隨區塊結束自動消失。

---

# Part E：使用 `malloc()` 動態配置

## Section X. `malloc()` 基本介面

### 29. 標準函式宣告

需要：

```c
#include <stdlib.h>
```

介面：

```c
void *malloc(size_t size);
```

---

### 30. `size` 的意思

`size` 表示：

```text
要配置多少位元組
```

型別為：

```text
size_t
```

它是用來表示物件大小的非負整數型別。

---

### 31. 使用 `sizeof` 計算空間

配置一個 `int`：

```c
malloc(sizeof(int));
```

配置十個 `int`：

```c
malloc(sizeof(int) * 10);
```

更容易隨指標型別維護的寫法：

```c
malloc(sizeof(numbers[0]) * 10);
```

或：

```c
malloc(sizeof(*numbers) * 10);
```

### 32. 不要寫死 `int` 大小

不建議：

```c
malloc(10 * 4);
```

C 不保證所有環境的 `int` 都是四位元組。

---

### 33. `malloc()` 的回傳值

成功：

```text
回傳新配置空間的起始位址
```

失敗：

```text
回傳 NULL
```

在 C 中，`void *` 可轉成其他物件指標，因此不需要為 `malloc()` 回傳值加強制轉型。

---

## Section XI. 基本動態陣列

### 34. 配置五個整數

```c
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int *numbers =
        malloc(5 * sizeof(numbers[0]));

    if (numbers == NULL) {
        fprintf(stderr, "Memory allocation failed.\n");
        return 1;
    }

    for (int i = 0; i < 5; i++) {
        numbers[i] = (i + 1) * 10;
    }

    for (int i = 0; i < 5; i++) {
        printf("%d ", numbers[i]);
    }

    printf("\n");

    free(numbers);

    return 0;
}
```

---

### 35. 動態空間也可以使用下標

只要 `numbers` 指向至少五個連續 `int`：

```c
numbers[0]
numbers[1]
...
numbers[4]
```

都能像陣列元素一樣存取。

但 `numbers` 本身仍是指標，不是陣列物件。

---

### 36. `malloc()` 不會初始化內容

剛配置後：

```c
int *numbers =
    malloc(5 * sizeof(numbers[0]));
```

元素值是不確定的。

必須先寫入：

```c
numbers[i] = value;
```

才能安全讀取。

若需要零初始化，可以使用後續可能學到的 `calloc()`；本章來源主要使用 `malloc()`。

---

## Section XII. 來源方式：每次建立大一格的新空間

### 37. 動態配置替代 VLA

來源將：

```c
int larger[length + 1];
```

改成：

```c
int *larger =
    malloc((length + 1) * sizeof(larger[0]));
```

`larger` 指向動態配置空間。

---

### 38. 動態配置不會在迴圈右大括號自動消失

指標變數 `larger` 本身仍是自動變數，但它所指向的動態空間不會因為離開區塊而自動釋放。

因此將位址保存到：

```c
numbers = larger;
```

後，下一次迴圈仍可以透過 `numbers` 使用該配置。

---

### 39. 仍然需要配置失敗檢查

來源的逐步程式直接使用 `larger`。

安全版本必須先檢查：

```c
if (larger == NULL) {
    /* 原 numbers 仍有效 */
}
```

在配置失敗前，不要覆蓋原指標，也不要嘗試複製到 `NULL`。

---

# Part F：使用 `free()` 歸還記憶體

## Section XIII. 為什麼需要 `free()`？

### 40. 動態配置不會自動釋放

若每次輸入都：

1. 配置大一格的新空間。
2. 複製資料。
3. 讓 `numbers` 指向新空間。

但從未釋放舊空間，舊配置會一直存在。

---

### 41. 記憶體洩漏

概念：

```text
舊配置仍然被系統視為已借出
但程式已失去它的位址
```

程式無法再使用或釋放它。

這稱為：

```text
Memory leak
記憶體洩漏
```

持續發生時，程式所占記憶體會不斷增加。

---

## Section XIV. `free()` 基本介面

### 42. 標準函式宣告

```c
void free(void *ptr);
```

位於：

```c
#include <stdlib.h>
```

---

### 43. `ptr` 必須是什麼？

`ptr` 應為：

- `NULL`；或
- 由 `malloc()`、`realloc()` 等配置函式成功回傳，且尚未釋放的位址。

不能傳入：

- 一般自動變數位址
- 陣列內部任意元素位址
- 已經釋放過的位址
- 未初始化指標

---

### 44. 何時釋放舊配置？

順序必須是：

1. 配置新空間。
2. 確認配置成功。
3. 將舊資料複製到新空間。
4. `free(numbers);`
5. `numbers = larger;`

不能在複製前釋放，否則舊資料已不能再讀取。

---

  <img
    src="images/lesson_24/C_Lesson_24_img06_manual_growth.png"

### 45. 手動擴充函式

```c
#include <stddef.h>
#include <stdlib.h>

int *grow_by_one(
    int *numbers,
    size_t length
) {
    int *larger =
        malloc((length + 1) * sizeof(larger[0]));

    if (larger == NULL) {
        return NULL;
    }

    for (size_t i = 0; i < length; i++) {
        larger[i] = numbers[i];
    }

    free(numbers);

    return larger;
}
```

呼叫者必須知道：

- 回傳非 `NULL`：新配置已接管資料，舊配置已釋放。
- 回傳 `NULL`：函式沒有釋放舊 `numbers`，呼叫者仍負責舊配置。

由於只回傳一個指標，實務上更常直接使用 `realloc()` 或設計更清楚的介面。

---

### 46. `free(NULL)` 是安全的

```c
int *numbers = NULL;

free(numbers);
```

不會做任何事。

來源投影片使用：

```c
int *numbers = 0;
```

在指標語境中，整數常數 `0` 是空指標常數；使用 `NULL` 更清楚。

---

### 47. 為什麼初始值不能未設定？

危險：

```c
int *numbers;

free(numbers);
```

`numbers` 的值不確定，並不一定是合法配置位址或 `NULL`。

來源在第一次迴圈就可能執行 `free(numbers)`，因此需要先初始化：

```c
int *numbers = NULL;
```

---

## Section XV. 釋放後的指標

### 48. `free()` 不會自動修改指標變數

```c
free(numbers);
```

之後，`numbers` 中可能仍保存原本的數字位址。

但該空間已不再屬於程式。

---

### 49. 釋放後使用

錯誤：

```c
free(numbers);

printf("%d\n", numbers[0]);
```

屬於未定義行為。

---

### 50. 重複釋放

錯誤：

```c
free(numbers);
free(numbers);
```

若中間沒有重新配置並更新指標，第二次釋放屬於未定義行為。

---

### 51. 設為 `NULL`

```c
free(numbers);
numbers = NULL;
```

好處：

- 避免誤以為它仍指向有效配置。
- 再次 `free(numbers)` 不會出錯，因為 `free(NULL)` 安全。
- 可以使用 `numbers == NULL` 表示目前沒有配置。

但這不能修正其他仍保存舊位址的指標。

## Section XVI. 使用 `malloc()`、複製與 `free()` 的完整版本

```c
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int *numbers = NULL;
    size_t length = 0;

    while (1) {
        int input;

        if (scanf("%d", &input) != 1) {
            break;
        }

        if (input == 0) {
            break;
        }

        int *larger =
            malloc((length + 1) * sizeof(larger[0]));

        if (larger == NULL) {
            fprintf(stderr, "Memory allocation failed.\n");
            free(numbers);
            return 1;
        }

        for (size_t i = 0; i < length; i++) {
            larger[i] = numbers[i];
        }

        free(numbers);
        numbers = larger;

        numbers[length] = input;
        length++;
    }

    printf("Numbers: ");

    for (size_t i = 0; i < length; i++) {
        printf("%d ", numbers[i]);
    }

    printf("\n");

    free(numbers);

    return 0;
}
```

這個版本正確管理記憶體，但每次新增元素都要配置、複製與釋放一次，效率不佳。

# Part G：使用 `realloc()` 重新配置

## Section XVII. `realloc()` 基本介面

### 52. 標準函式宣告

```c
void *realloc(void *ptr, size_t size);
```

需要：

```c
#include <stdlib.h>
```

---

### 53. `ptr` 的意思

`ptr` 是要重新配置之動態記憶體空間的起始位址。

通常原本來自：

```c
malloc()
realloc()
calloc()
```

不能把一般自動陣列交給 `realloc()`。

---

### 54. `size` 的意思

`size` 是重新配置完成後需要的**總位元組數**，不是要增加的位元組數。

例如原本三個 `int`，要變成四個：

```c
realloc(
    numbers,
    4 * sizeof(numbers[0])
);
```

---

### 55. `realloc()` 保留什麼內容？

成功時，舊資料中可容納於新大小的前段內容會被保留。

擴大：

```text
[1][2][3]
→
[1][2][3][?]
```

新增部分的內容未初始化。

縮小：

```text
[1][2][3][4]
→
[1][2]
```

超出新大小的後段資料不再存在。

---

### 56. 可能原地擴充，也可能搬家

`realloc()` 可能：

- 在原位置擴大；
- 或配置另一塊空間、複製內容，再釋放原空間。

因此成功後必須使用它的回傳位址。

不能假設新位址與舊位址相同。

---

  <img
    src="images/lesson_24/C_Lesson_24_img08_realloc_move_or_stay.png"
    alt="realloc 可能原地擴充也可能搬到新位置"
    width="700">
</p>


### 57. 成功後的舊指標

只要 `realloc()` 成功，原來傳入的指標值便不能再被當成有效配置使用，即使新位址數字看起來相同。

應只保留並使用回傳值。

---

## Section XVIII. 來源的簡化版本

來源將四個步驟：

```text
malloc
複製
free
改指向
```

改成：

```c
numbers = realloc(
    numbers,
    (length + 1) * sizeof(numbers[0])
);
```

這大幅簡化程式，但直接賦值存在配置失敗風險。

---

## Section XIX. 配置失敗與暫存指標

### 58. `realloc()` 失敗時

當 `size > 0` 且重新配置失敗：

```text
回傳 NULL
原本的配置仍然存在且內容不變
```

---

### 59. 危險的直接賦值

```c
numbers = realloc(numbers, new_size);
```

若失敗：

```text
numbers 變成 NULL
原配置仍存在
但程式失去原配置位址
```

造成記憶體洩漏。

---

### 60. 安全接收方式

```c
int *temporary =
    realloc(numbers, new_size);

if (temporary == NULL) {
    /* numbers 仍指向舊配置 */
} else {
    numbers = temporary;
}
```

---

  <img
    src="images/lesson_24/C_Lesson_24_img09_safe_realloc.png"
    alt="使用暫存指標安全接收 realloc 結果"
    width="700">
</p>


### 61. `realloc(NULL, size)`

```c
int *numbers = NULL;

int *temporary =
    realloc(numbers, 5 * sizeof(numbers[0]));
```

效果等同於配置新空間，可用於第一次配置。

---

### 62. 避免使用 `realloc(ptr, 0)`

不同標準版本與實作對零大小重新配置的細節容易造成混淆。

需要釋放時，直接使用：

```c
free(ptr);
ptr = NULL;
```

更清楚。

---

## Section XX. 使用 `realloc()` 的完整版本

```c
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int *numbers = NULL;
    size_t length = 0;

    while (1) {
        int input;

        if (scanf("%d", &input) != 1) {
            break;
        }

        if (input == 0) {
            break;
        }

        int *temporary =
            realloc(
                numbers,
                (length + 1) * sizeof(numbers[0])
            );

        if (temporary == NULL) {
            fprintf(stderr, "Memory allocation failed.\n");
            free(numbers);
            return 1;
        }

        numbers = temporary;
        numbers[length] = input;
        length++;
    }

    printf("Numbers: ");

    for (size_t i = 0; i < length; i++) {
        printf("%d ", numbers[i]);
    }

    printf("\n");

    free(numbers);

    return 0;
}
```

這個版本與來源概念一致，但安全保留舊指標直到 `realloc()` 成功。

# Part H：容量與效率

## Section XXI. 每次只擴大一格的問題

### 63. 配置次數很多

輸入 `n` 個整數時，每次都擴大一格：

```text
1 格
2 格
3 格
...
n 格
```

可能觸發 `n` 次重新配置。

---

### 64. 可能重複搬移大量資料

若每次都需要搬家，複製量大約是：

```text
1 + 2 + 3 + ... + (n - 1)
```

資料量大時效率較差。

來源 `realloc()` 投影片指出，重新配置可能不必搬家，因此通常比手動每次配置與複製更有效率；但仍不能保證每次都原地完成。

---

## Section XXII. 分辨 `size` 與 `capacity`

```c
size_t size = 0;
size_t capacity = 0;
int *numbers = NULL;
```

- `size`：目前實際保存幾個元素。
- `capacity`：目前已配置空間可容納幾個元素。

只有在：

```c
size == capacity
```

時才需要擴充。

---

## Section XXIII. 容量倍增策略

### 65. 常見策略

第一次配置：

```text
capacity = 4
```

空間用完時：

```text
capacity *= 2
```

容量變化：

```text
0 → 4 → 8 → 16 → 32 ...
```

---


<p align="center">
  <img
    src="images/lesson_24/C_Lesson_24_img10_capacity_doubling.png"
    alt="動態陣列使用容量倍增降低重新配置次數"
    width="700">
</p>


### 66. 優點

多數新增操作只需要：

```c
numbers[size] = input;
size++;
```

不需要每次都重新配置。

---

### 67. 安全容量倍增完整程式

```c
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int *numbers = NULL;
    size_t size = 0;
    size_t capacity = 0;

    while (1) {
        int input;

        if (scanf("%d", &input) != 1) {
            break;
        }

        if (input == 0) {
            break;
        }

        if (size == capacity) {
            size_t new_capacity =
                capacity == 0 ? 4 : capacity * 2;

            if (
                new_capacity < capacity ||
                new_capacity >
                    SIZE_MAX / sizeof(numbers[0])
            ) {
                fprintf(stderr, "Requested size is too large.\n");
                free(numbers);
                return 1;
            }

            int *temporary =
                realloc(
                    numbers,
                    new_capacity * sizeof(numbers[0])
                );

            if (temporary == NULL) {
                fprintf(stderr, "Memory allocation failed.\n");
                free(numbers);
                return 1;
            }

            numbers = temporary;
            capacity = new_capacity;
        }

        numbers[size] = input;
        size++;
    }

    printf("Numbers: ");

    for (size_t i = 0; i < size; i++) {
        printf("%d ", numbers[i]);
    }

    printf("\n");
    printf("Size: %zu\n", size);
    printf("Capacity: %zu\n", capacity);

    free(numbers);

    return 0;
}
```

---

### 68. 為什麼可能有未使用空間？

若目前：

```text
size     = 6
capacity = 8
```

最後兩格尚未保存有效資料。

這是以少量額外空間換取較少重新配置次數。

# Part I：常見記憶體問題

## Section XXIV. 記憶體洩漏

### 69. 遺失唯一指標

```c
int *numbers =
    malloc(10 * sizeof(numbers[0]));

numbers =
    malloc(20 * sizeof(numbers[0]));
```

第二次賦值前沒有 `free()`，第一塊配置的位址遺失。

---

### 70. 修正

```c
free(numbers);

numbers =
    malloc(20 * sizeof(numbers[0]));
```

但若目的是保留舊內容並調整大小，優先考慮安全使用 `realloc()`。

---

## Section XXV. 釋放後使用

```c
free(numbers);

numbers[0] = 10;
```

錯誤。

`free()` 後配置不再屬於程式。

---

## Section XXVI. 重複釋放

```c
free(numbers);
free(numbers);
```

錯誤。

可在第一次後：

```c
numbers = NULL;
```

---

## Section XXVII. 釋放錯誤位址

```c
int values[10];

free(values);
```

錯誤。`values` 是自動陣列，不是動態配置所得。

---

### 71. 不能釋放配置中間位置

```c
int *numbers =
    malloc(10 * sizeof(numbers[0]));

free(numbers + 1);
```

錯誤。

必須將動態配置函式回傳的起始位址交給 `free()`。

---

## Section XXVIII. 配置後未檢查

```c
int *numbers =
    malloc(10 * sizeof(numbers[0]));

numbers[0] = 1;
```

如果配置失敗，`numbers == NULL`，間接存取會出錯。

---

## Section XXIX. 配置後讀取未初始化內容

```c
int *numbers =
    malloc(10 * sizeof(numbers[0]));

printf("%d\n", numbers[0]);
```

錯誤。

`malloc()` 不會將元素自動設為零。

## Section XXXIV. 做題時可以使用的提示

### 1. 先找出所有配置點

```c
malloc(...)
realloc(...)
```

每一個成功配置都要能追蹤到最終釋放。

---

### 2. 建立所有權表

| 指標 | 指向哪一塊配置 | 誰負責 `free()` |
| --- | --- | --- |
| `numbers` | 目前動態陣列 | `main()` |
| `temporary` | 只有 `realloc()` 成功後短暫保存 | 成功後交給 `numbers` |

---

### 3. 擴充前先保存舊位址

不要在確認新配置成功前覆蓋唯一的舊位址。

---

### 4. 配置位元組數公式

```c
element_count * sizeof(pointer[0])
```

---

### 5. 釋放前問三件事

1. 這個位址是否來自動態配置函式？
2. 是否仍是該配置的起始位址？
3. 是否尚未釋放？

---

### 6. 釋放後立即更新程式狀態

```c
free(pointer);
pointer = NULL;
capacity = 0;
size = 0;
```

是否清除 `size`、`capacity` 取決於資料結構是否整體重設。

---

### 7. `realloc()` 後不要使用舊的其他指標

若還有指標指向原配置內部元素，成功重新配置後它們都可能失效。

---

### 8. 建議測試資料

```text
立即輸入 0
只輸入一個數
剛好填滿第一次容量
超過第一次容量
需要多次擴充
輸入格式錯誤
```

## Section XXXVII. 常見錯誤提醒

### 錯誤 1：未限制固定陣列寫入數量

```c
numbers[length] = input;
length++;
```

但沒有檢查 `length < capacity`。

---

### 錯誤 2：以為宣告後可以改變陣列大小

陣列物件大小已固定。

---

### 錯誤 3：使用長度為零的陣列

標準 C 陣列不能宣告為零長度。

---

### 錯誤 4：把 VLA 當成跨區塊存在的動態空間

VLA 仍是自動物件。

---

### 錯誤 5：將 VLA 位址保存到外部指標後繼續使用

區塊結束後形成懸空指標。

---

### 錯誤 6：以為指標能控制被指向物件生命週期

指標只保存位址。

---

### 錯誤 7：`malloc()` 大小使用元素數量而非位元組數

錯誤：

```c
malloc(10);
```

若目標是十個 `int`，應乘上元素大小。

---

### 錯誤 8：強制假設 `sizeof(int) == 4`

不可攜。

---

### 錯誤 9：未檢查 `malloc()` 回傳值

可能間接存取 `NULL`。

---

### 錯誤 10：立即讀取 `malloc()` 內容

內容尚未初始化。

---

### 錯誤 11：配置新空間後遺失舊指標

造成記憶體洩漏。

---

### 錯誤 12：在複製舊資料前先 `free()`

造成釋放後讀取。

---

### 錯誤 13：將未初始化指標交給 `free()`

未定義行為。

---

### 錯誤 14：釋放自動陣列

```c
int values[10];

free(values);
```

錯誤。

---

### 錯誤 15：釋放配置中間位置

```c
free(numbers + 1);
```

錯誤。

---

### 錯誤 16：`free()` 後繼續讀寫

屬於 use after free。

---

### 錯誤 17：重複 `free()`

屬於 double free。

---

### 錯誤 18：認為 `free()` 會自動把指標設為 `NULL`

它不會修改呼叫端指標變數。

---

### 錯誤 19：將 `realloc()` 第二個引數當成增加量

它是新總位元組數。

---

### 錯誤 20：假設 `realloc()` 位址必定不變

它可能搬家。

---

### 錯誤 21：直接覆蓋原指標

```c
numbers = realloc(numbers, new_size);
```

失敗時會遺失原配置位址。

---

### 錯誤 22：重新配置成功後繼續使用舊的元素指標

配置搬家後，指向舊配置內部的指標會失效。

---

### 錯誤 23：每次新增一筆都重新配置一格

可以運作，但資料量大時效率較差。

---

### 錯誤 24：混淆 `size` 與 `capacity`

迴圈輸出應走訪 `size`，不是尚未使用的整個 `capacity`。

```mermaid
    C -- 否 --> F[保留舊空間並處理錯誤]
    C -- 是 --> D[複製舊資料]
```

```mermaid
flowchart TD
    A[執行進入區塊] --> B[自動物件開始存在]
```

```mermaid
flowchart TD
    A[指標保存自動陣列位址] --> B[離開陣列所在區塊]
```

```mermaid
flowchart TD
```
