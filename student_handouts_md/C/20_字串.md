# Lesson 20：Strings 字串

> 這堂課的重點：理解 C 語言字串其實是以 `'\0'` 結束的 `char` 陣列，分辨陣列配置大小與文字實際長度，並從標準輸入 `stdin` 逐字元讀入一整行文字。接著處理輸入長度超過陣列容量時的緩衝區溢位與剩餘輸入問題，最後學會檢查 `scanf()` 的回傳值，避免讀取失敗後使用未初始化資料或陷入無限重試。

## Section II. 今天的學習方式

1. 先在紙上為每個字元畫一格陣列元素。
2. 將 `"Hello world"` 的十一個可見字元逐格寫入。
3. 在最後額外畫一格 `'\0'`。
4. 同時標記：
   - 陣列配置大小
   - 第一個 `'\0'` 的索引
   - 文字實際長度
5. 比較：
   ```c
   sizeof(str)
   ```
   與：
   ```c
   str_len(str)
   ```
6. 手動追蹤 `str_len()` 中 `i` 的變化。
7. 讀入文字時，畫出三個區域：
   - 鍵盤與終端
   - `stdin`
   - 程式內的字元陣列
8. 每執行一次 `%c`，就從 `stdin` 移除一個字元並寫入陣列。
9. 看到 `'\n'` 時，不將它保留為文字內容，而改寫成 `'\0'`。
10. 所有輸入陣列都先明確寫出容量。
11. 先計算可保存的最大文字長度：
    ```text
    陣列容量 - 1
    ```
12. 對過長輸入分別追蹤：
    - 已保存的部分
    - 仍留在 `stdin` 的部分
13. 整數輸入失敗時，不只看畫面結果，也畫出 `stdin` 中仍未被消耗的字元。
14. 每一次呼叫 `scanf()` 都檢查回傳值。
15. 遇到 `EOF` 時停止，不要無限等待或無限清除。
16. 先依來源完成逐步版本，再使用清楚標示的安全整理版修正邊界問題。
17. 本章不把來源未提供的函式當成主要推導；額外方法會明確標示為教材補充。
18. 所有完整且預期合法的 C 程式都使用嚴格 C17 選項編譯。

## Section III. 今天會學到的內容

| 主題 | 你需要知道的事 |
| --- | --- |
| 字元 | 一個 `char` 值，例如 `'H'` |
| 字串 | 以 `'\0'` 結束的 `char` 陣列 |
| 字串字面常數 | 使用雙引號表示的文字，例如 `"Hello"` |
| 結束字元 | `'\0'`，用來標示字串內容結束 |
| 換行字元 | `'\n'`，通常由按下 Enter 產生 |
| 陣列配置大小 | 陣列實際擁有的元素數量 |
| 字串長度 | 第一個 `'\0'` 之前的字元數量 |
| `sizeof(array)` | 完整陣列所占的位元組數 |
| `str_len()` | 來源自行實作的字串長度函式 |
| `%s` | 從第一個字元輸出到 `'\0'` |
| `%c` | 一次讀入或輸出一個字元 |
| `stdin` | 程式的標準輸入資料流 |
| blocking | 沒有可讀資料時，輸入函式等待 |
| 輸入緩衝 | 尚未被程式讀取的輸入內容 |
| 緩衝區溢位 | 寫入超過目標陣列容量 |
| 最大文字長度 | 一般為容量減一，預留 `'\0'` |
| 截短 | 只保留可容納的前段文字 |
| 剩餘輸入 | 截短後仍留在 `stdin` 的同一行內容 |
| 清除一行 | 持續讀取直到 `'\n'` 或 `EOF` |
| `scanf()` 回傳值 | 成功完成指定與寫入的資料筆數 |
| 轉換失敗 | 輸入不符合格式，例如用 `%d` 讀 `abc` |
| 未初始化變數 | 尚未取得可安全讀取的值 |
| `EOF` | 輸入來源已結束，無法再讀取資料 |
| 無限失敗迴圈 | 無效字元留在 `stdin`，重試時一直讀到同一內容 |

### 6. 部分初始化會把剩餘元素設為 `0`

```c
char str[15] = {
    'H', 'e', 'l', 'l', 'o', ' ',
    'w', 'o', 'r', 'l', 'd'
};
```

前十一格是文字，其餘四格會初始化為零。

所以第一個剩餘元素可作為 `'\0'`。

---

### 7. `char str[11] = "Hello world";` 不是正常 C 字串

它可以保存十一個可見字元，但沒有空間保存結尾 `'\0'`。

因此不能安全交給依賴 `'\0'` 的函式，例如：

```c
printf("%s\n", str);
```

或來源的：

```c
str_len(str);
```

---

### 8. `char str[10] = "Hello world";` 容量不足

十一個可見字元本身就放不下，更不用說 `'\0'`。

編譯器必須對不相容的初始化提供診斷。

---

### 9. `%s` 需要有效的 C 字串

```c
printf("%s\n", str);
```

會從 `str[0]` 開始，持續讀取直到遇到 `'\0'`。

若陣列內沒有 `'\0'`，會讀到陣列外部並造成未定義行為。

---

### 10. 來源的 `str_len()` 假設一定能找到 `'\0'`

```c
while (str[i] != '\0') {
    i++;
}
```

如果傳入的字元陣列沒有 `'\0'`，迴圈會越界。

---

### 11. `stdin` 可以理解成程式的輸入資料流

來源用「像檔案一樣」的方式說明：

- 按下 Enter 後，輸入資料進入 `stdin`。
- `scanf()` 從 `stdin` 讀取。
- 沒有可讀資料時，程式可能等待。

這是理解輸入殘留問題的重要模型。

---

### 12. `%c` 不會忽略空白

```c
scanf("%c", &ch);
```

可以讀到：

- 英文字母
- 空格
- Tab
- 換行字元

因此適合逐字元讀取一整行。

---

### 13. 沒有容量限制的來源初版可能溢位

```c
while (1) {
    scanf("%c", &str[i]);

    if (str[i] == '\n') {
        break;
    }

    i++;
}
```

如果輸入一直沒有換行，而且長度超過陣列容量，`i` 會繼續增加並寫到陣列外部。

---

### 14. 容量必須包含 `'\0'`

```c
char str[15];
```

最多安全保存：

```text
14 個文字字元 + 1 個 '\0'
```

### 15. 來源把 `14` 當成最大文字長度傳入

```c
str_read(str, 14);
```

對：

```c
char str[15];
```

而言，`14` 是可保存的最大文字字元數。

---

### 16. 只限制寫入長度仍可能留下輸入

輸入超過十四個字元時，函式只能保存前十四個。

同一行剩下的字元與 `'\n'` 仍在 `stdin`。

---

### 17. 下一次讀取可能直接讀到上一行剩餘內容

來源示範將過長的：

```text
Hello, "C" world!
```

拆成兩次輸出：

```text
Hello, "C" wor
ld!
```

使用者沒有再次輸入，第二次呼叫已經從 `stdin` 取得剩餘部分。

---

### 18. 截短後要丟棄同一行剩餘內容

概念流程：

```text
儲存到容量上限
→ 若尚未讀到 '\n'
→ 繼續讀取但不保存
→ 直到 '\n' 或 EOF
```

### 19. 來源用 `str[i] != '\n'` 判斷是否需要清除

來源後段加入：

```c
if (str[i] != '\n') {
    /* 讀到換行為止 */
}
```

但當迴圈因 `i == n` 結束時，`str[i]` 尚未由輸入寫入，直接讀取它並不是理想的狀態判斷。

本講義保留來源推導，再提供使用明確讀取狀態的安全整理版。

---

### 20. `scanf("%d")` 會忽略前導空白

輸入：

```text
     3
```

仍可成功讀入整數 `3`。

這種忽略空白的行為與 `%c` 不同。

---

### 21. `scanf("%d")` 遇到 `abc` 時不會寫入整數

```c
int number;
scanf("%d", &number);
```

如果沒有成功轉換，`number` 不會因此得到一個新的合法整數。

如果它原本尚未初始化，接著輸出它會造成未定義行為。

### 22. 必須檢查 `scanf()` 回傳值

```c
if (scanf("%d", &number) == 1) {
    /* 成功 */
}
```

`1` 表示成功完成一個指定寫入。

---

### 23. 讀取失敗後，無效字元仍可能留在 `stdin`

`%d` 看到字母 `a`，判斷無法開始整數轉換後便失敗。

該字元沒有自動消失。

---

### 24. 直接重試會再次看到同一個字元

錯誤模式：

```c
while (scanf("%d", &number) != 1) {
    printf("Error\n");
}
```

若 `a` 一直留在 `stdin`，每一次重試都立即失敗，形成無限錯誤輸出。

---

### 25. 清除失敗輸入時也要考慮 `EOF`

不能只寫：

```c
while (getchar() != '\n') {
}
```

若輸入已結束而沒有換行，會一直得到 `EOF`。

安全停止條件應同時檢查：

```text
'\n' 或 EOF
```

## Section V. 核心概念說明

## Section V-A. C 字串是 `char` 陣列

### 1. 最基本的字串初始化

```c
#include <stdio.h>

int main(void) {
    char str[] = "Hello world";

    printf("%s\n", str);

    return 0;
}
```

`str` 的型態是字元陣列。

---

### 2. 查看完整陣列大小

```c
#include <stdio.h>

int main(void) {
    char str[] = "Hello world";

    printf("Array size: %zu\n", sizeof(str));

    return 0;
}
```

輸出：

```text
Array size: 12
```

---

### 3. 為什麼是 `12`？

| 索引 | 內容 |
| ---: | --- |
| 0 | `'H'` |
| 1 | `'e'` |
| 2 | `'l'` |
| 3 | `'l'` |
| 4 | `'o'` |
| 5 | `' '` |
| 6 | `'w'` |
| 7 | `'o'` |
| 8 | `'r'` |
| 9 | `'l'` |
| 10 | `'d'` |
| 11 | `'\0'` |

---

## Section V-B. 自行計算字串長度

### 4. 來源的 `str_len()` 推導

第一步是找到第一個 `'\0'`。

```c
int str_len(char str[]) {
    int i = 0;

    while (str[i] != '\0') {
        i++;
    }

    return i;
}
```

---

### 5. 完整範例

```c
#include <stdio.h>

int str_len(char str[]);

int main(void) {
    char str[] = "Hello world";

    printf("Array size: %zu\n", sizeof(str));
    printf("Text length: %d\n", str_len(str));

    return 0;
}

int str_len(char str[]) {
    int i = 0;

    while (str[i] != '\0') {
        i++;
    }

    return i;
}
```

輸出：

```text
Array size: 12
Text length: 11
```

---

### 6. `i` 的追蹤

```text
i = 0  → 'H'
i = 1  → 'e'
...
i = 10 → 'd'
i = 11 → '\0'，停止
```

回傳：

```text
11
```

```c
#include <stdio.h>

int main(void) {
    char str[12] = {
        'H', 'e', 'l', 'l', 'o', ' ',
        'w', 'o', 'r', 'l', 'd', '\0'
    };

    printf("%s\n", str);

    return 0;
}
```

---

### 8. 使用部分初始化

```c
#include <stdio.h>

int main(void) {
    char str[15] = {
        'H', 'e', 'l', 'l', 'o', ' ',
        'w', 'o', 'r', 'l', 'd'
    };

    printf("Array size: %zu\n", sizeof(str));
    printf("%s\n", str);

    return 0;
}
```

未明確列出的元素自動為 `0`。

---

### 9. 使用字串字面常數

```c
char str[15] = "Hello world";
```

會將字元與結尾 `'\0'` 放入陣列，其餘元素初始化為 `0`。

---

### 10. 省略陣列大小

```c
char str[] = "Hello world";
```

```text

```

## Section V-D. 沒有結束字元的字元陣列

### 11. 剛好只有文字內容的陣列

```c

char str[11] = "Hello world";
```

## Section V-E. 從鍵盤讀入一整行

### 13. 題目

讓使用者輸入一行文字：

```text
Hello world
```

再將同一行重現輸出：

```text
Hello world
```

---

### 14. `stdin` 的來源模型

一般終端操作可以理解為：

```text
鍵盤輸入文字
→ 按下 Enter
→ 文字與換行進入 stdin
→ scanf 從 stdin 讀取
```

如果 `stdin` 沒有可讀的新資料，輸入函式可能等待。

---

### 15. 先讀一個字元

```c
char ch;

scanf("%c", &ch);
```

`%c` 讀取下一個字元，不會自動忽略空白。

---

### 16. 讀到換行為止

```c
while (1) {
    char ch;

    scanf("%c", &ch);

    if (ch == '\n') {
        break;
    }
}
```

這個版本只讀取，還沒有保存到陣列。

---

### 17. 將字元寫入陣列

```c
int i = 0;

while (1) {
    scanf("%c", &str[i]);

    if (str[i] == '\n') {
        break;
    }

    i++;
}
```

---

### 18. 將換行改成字串結尾

```c
str[i] = '\0';
```

此時：

- `str[0]` 到 `str[i - 1]` 是文字內容。
- `str[i]` 是 `'\0'`。
- 原本的 `'\n'` 不保留在字串中。

---

### 19. 來源初版完整程式

```c
#include <stdio.h>

void str_read(char str[]);

int main(void) {
    char str[15];

    str_read(str);
    printf("%s\n", str);

    return 0;
}

void str_read(char str[]) {
    int i = 0;

    while (1) {
        if (scanf("%c", &str[i]) != 1) {
            str[i] = '\0';
            return;
        }

        if (str[i] == '\n') {
            break;
        }

        i++;
    }

    str[i] = '\0';
}
```

這個版本加入了回傳值檢查，但仍沒有容量限制。

## Section V-F. 緩衝區溢位

### 20. 危險情況

```c
char str[15];
```

若使用者輸入超過十四個文字字元，無上限迴圈會嘗試寫入：

```c
str[15]
str[16]
...
```

這些位置不屬於陣列。

---

### 21. 為什麼最多是十四個文字字元？

```text
陣列容量：15
文字內容：最多 14
結束字元：1
```

---

### 22. 將最大文字長度傳入

來源修改介面：

```c
void str_read(char str[], int maximum_length);
```

呼叫：

```c
char str[15];

str_read(str, 14);
```

---

### 23. 有上限的來源版本

```c
#include <stdio.h>

void str_read(char str[], int maximum_length);

int main(void) {
    char str[15];

    str_read(str, 14);
    printf("%s\n", str);

    return 0;
}

void str_read(char str[], int maximum_length) {
    int i;

    for (i = 0; i < maximum_length; i++) {
        if (scanf("%c", &str[i]) != 1) {
            break;
        }

        if (str[i] == '\n') {
            break;
        }
    }

    str[i] = '\0';
}
```

這個版本保護了目標陣列，但過長輸入的剩餘部分仍留在 `stdin`。

## Section V-H. 安全整理版的行輸入函式

### 27. 使用容量而不是「最大文字長度」

以下是依來源問題整理的安全版本。

介面：

```c
int str_read_line(char str[], int capacity);
```

`capacity` 表示完整陣列容量，包括 `'\0'` 的位置。

---

### 28. 完整安全版本

```c
#include <stdio.h>

int str_read_line(char str[], int capacity);

int main(void) {
    char str[15];

    if (str_read_line(str, 15)) {
        printf("%s\n", str);
    }

    return 0;
}

int str_read_line(char str[], int capacity) {
    int ch;
    int i = 0;

    if (capacity <= 0) {
        return 0;
    }

    while (
        i < capacity - 1 &&
        (ch = getchar()) != '\n' &&
        ch != EOF
    ) {
        str[i] = (char)ch;
        i++;
    }

    str[i] = '\0';

    if (ch != '\n' && ch != EOF) {
        do {
            ch = getchar();
        } while (ch != '\n' && ch != EOF);
    }

    return ch != EOF || i > 0;
}
```

---

### 29. 這個版本修正了什麼？

1. 不會寫到陣列外部。
2. 永遠預留一格給 `'\0'`。
3. 不讀取未初始化的 `str[i]` 判斷狀態。
4. 過長時會清除同一行剩餘內容。
5. 遇到 `EOF` 時可以停止。
6. 下一次呼叫不會讀到上一行被截斷的尾端。

---

### 30. 空行

使用者直接按 Enter：

```text
第一個讀到的字元是 '\n'
```

結果：

```c
str[0] = '\0';
```

字串長度為 `0`。

## Section V-J. `scanf()` 失敗後的後遺症

### 36. 看似合理但會卡住的版本

```c
while (scanf("%d", &number) != 1) {
    printf("Error: Invalid input\n");
}
```

輸入：

```text
abc
```

會不斷失敗。

---

### 37. 為什麼？

第一次 `%d` 在 `a` 失敗。

`a` 沒有被取走，所以第二次 `%d` 仍然看到同一個 `a`。

流程：

```text
讀到 a
→ 轉換失敗
→ a 留在 stdin
→ 再次讀到 a
→ 再次失敗
```

### 38. 安全丟棄無效行

```c
#include <stdio.h>

int main(void) {
    int number;

    while (1) {
        int result = scanf("%d", &number);

        if (result == 1) {
            break;
        }

        if (result == EOF) {
            return 0;
        }

        printf("Error: Invalid input\n");

        {
            int ch;

            do {
                ch = getchar();
            } while (ch != '\n' && ch != EOF);

            if (ch == EOF) {
                return 0;
            }
        }
    }

    printf("%d\n", number);

    return 0;
}
```

### 39. 為什麼要清除到換行？

若輸入：

```text

```

只丟棄第一個 `a`，後面仍有：

```text

```

最簡單的錯誤恢復方式是將整行視為無效，全部丟棄後再請使用者輸入新的一行。

| ---: | --- |

| 1 | 第一個成功，第二個失敗或輸入結束 |
| 0 | 第一個整數轉換就失敗 |

## Section V-L. 教材補充：使用標準函式庫的 `fgets()`

> 這一小節不是四份來源投影片的主要推導，而是把來源所處理的「容量限制、換行與剩餘輸入」對應到標準函式庫常用介面。

### 44. 基本使用

```c
#include <stdio.h>

int main(void) {
    char str[15];

    if (fgets(str, sizeof(str), stdin) != NULL) {
        printf("%s", str);
    }

    return 0;
}
```

`fgets()` 最多保存：

```text
sizeof(str) - 1
```

個字元，並補上 `'\0'`。

---

### 45. `fgets()` 可能保留換行

若容量足夠且有讀到換行，`'\n'` 會保留在字串中。

可自行尋找並改成 `'\0'`。

---

### 46. `fgets()` 也可能留下過長行的尾端

它避免寫入溢位，但如果一行比陣列可容納範圍更長，剩餘內容仍在 `stdin`。

因此來源教材中「清除同一行剩餘資料」的概念仍然重要。

---

## Section V-M. 容易搞混的重點

### 47. `sizeof(str)` 不是永遠等於文字長度加一

只有當：

- `str` 是完整陣列
- 第一個 `'\0'` 剛好在最後一格

兩者才剛好相差一。

例如：

```c
char str[15] = "Hello";
```

```text
sizeof(str) = 15
字串長度 = 5
```

---

### 48. 多個 `'\0'` 不會增加字串長度

字串長度只看第一個 `'\0'`。

---

### 49. 陣列有足夠空間，不代表目前一定是有效字串

```c
char str[100];
```

如果尚未寫入 `'\0'`，仍不能直接用 `%s`。

---

### 50. 截短不是溢位

安全截短：

```text
只保存容量允許的前段
```

溢位：

```text
仍繼續寫到陣列外部
```

兩者不同。

---

### 51. 清除 `stdin` 不是標準函式名稱

不能假設存在：

```c
fflush(stdin);
```

標準 C 不把 `fflush()` 定義成清除輸入資料的通用方法。

來源採用逐字元讀到換行的概念。

---

### 52. `scanf()` 成功一次，不代表整行全部有效

輸入：

```text
123abc
```

`%d` 可以成功讀到 `123`，但：

```text
abc
```

仍可能留在 `stdin`。

---

### 53. `%d` 後面的換行通常不妨礙下一次 `%d`

因為 `%d` 會略過前導空白。

但換行會影響下一次 `%c` 或逐字元行輸入。

## Section XI. 重點複習

1. C 字串使用 `char` 陣列表示。
2. 有效 C 字串必須以 `'\0'` 結束。
3. 字串字面常數會包含隱藏的 `'\0'`。
4. `"Hello world"` 有十一個可見字元。
5. 保存 `"Hello world"` 的一般字串陣列至少需要十二格。
6. `sizeof()` 可以得到完整陣列配置大小。
7. `sizeof()` 不等於一般意義的文字長度。
8. 字串長度是第一個 `'\0'` 之前的字元數量。
9. 字串長度不包含 `'\0'`。
10. `'\0'` 與 `'0'` 不同。
11. `'\0'` 與 `'\n'` 不同。
12. 部分初始化會將剩餘元素設為零。
13. 只放文字而沒有 `'\0'` 的陣列不是安全 C 字串。
14. `%s` 會讀取到第一個 `'\0'`。
15. 沒有 `'\0'` 時使用 `%s` 會造成未定義行為。
16. 來源的 `str_len()` 逐一尋找 `'\0'`。
17. `str_len()` 也假設字串有效。
18. `stdin` 是程式的標準輸入資料流。
19. 終端輸入通常按下 Enter 後送入 `stdin`。
20. `scanf()` 從 `stdin` 取得資料。
21. 沒有資料時，輸入函式可能等待。
22. `%c` 一次讀取一個字元。
23. `%c` 不會自動略過空白。
24. 逐字元讀到 `'\n'` 可以取得完整一行。
25. 應將換行位置改成 `'\0'`。
26. 無容量限制的輸入函式可能寫出陣列範圍。
27. 字串陣列必須預留一格給 `'\0'`。
28. 容量 `15` 最多保存十四個一般文字字元。
29. 傳入最大長度可以避免目標陣列溢位。
30. 限制寫入不代表整行已經讀完。
31. 過長輸入的尾端仍可能留在 `stdin`。
32. 下一次讀取可能取得上一行的剩餘內容。
33. 截短時應丟棄到 `'\n'` 或 `EOF`。
34. 安全版本應使用明確讀取狀態，而不是讀取未初始化元素判斷。
35. 空行會形成長度為零的字串。
36. `%d` 會略過前導空白。
37. `%d` 遇到不相容字元會轉換失敗。
38. 讀取失敗時，目標整數不會得到合法新值。
39. 未初始化整數不可直接輸出。
40. `scanf()` 回傳成功完成的指定數量。
41. 讀取一個整數成功時回傳 `1`。
42. 讀取失敗時應顯示錯誤，而不是使用變數。
43. 無效字元通常仍留在 `stdin`。
44. 不清除無效輸入便重試，可能無限失敗。
45. 清除輸入時要同時檢查 `'\n'` 與 `EOF`。
46. `123abc` 可以成功讀到 `123`，但留下 `abc`。
47. `%d` 後的空白通常不影響下一次 `%d`。
48. `%d` 後的換行會影響下一次 `%c` 或行輸入。
49. `fgets()` 是補充方法，也需要理解容量、換行與過長行尾端。
50. 下一階段會深入字串與指標的關係。

## Section XII. 常見錯誤提醒

### 錯誤 1：忘記預留 `'\0'`

```c
char str[11] = "Hello world";
```

不能安全當成一般字串。

---

### 錯誤 2：把 `sizeof(str)` 當成字串長度

容量可能比實際文字長很多。

---

### 錯誤 3：把 `'\0'` 寫成 `'0'`

兩者不是相同字元。

---

### 錯誤 4：把 `'\n'` 留在字串中卻又額外輸出換行

可能出現多一個空白行。

---

### 錯誤 5：用 `%s` 輸出沒有結束字元的陣列

會繼續讀到陣列外部。

---

### 錯誤 6：`str_len()` 沒有任何容量上限

傳入無效字串時會越界。

---

### 錯誤 7：逐字元輸入沒有檢查陣列容量

會造成緩衝區溢位。

---

### 錯誤 8：容量 `15` 卻允許保存十五個文字字元

還需要一格 `'\0'`。

---

### 錯誤 9：截短後沒有清除同一行尾端

下一次讀取會接續上一行。

---

### 錯誤 10：只讀到 `'\n'`，不處理 `EOF`

輸入結束時可能無限迴圈。

---

### 錯誤 11：使用未初始化的 `str[i]` 判斷是否截短

應使用讀取結果或明確狀態變數。

---

### 錯誤 12：認為增加固定陣列大小可以永久解決所有輸入問題

任何固定資源都有上限。

---

### 錯誤 13：未檢查 `scanf()` 回傳值

程式無法知道轉換是否成功。

---

### 錯誤 14：讀取失敗後仍輸出 `number`

如果未初始化，屬於未定義行為。

---

### 錯誤 15：無效輸入後只顯示錯誤，不消耗輸入

重試時會遇到同一字元。

---

### 錯誤 16：使用 `while (scanf(...) != 1)` 卻沒有錯誤恢復

容易形成無限迴圈。

---

### 錯誤 17：只丟棄一個無效字元

同一行後面仍可能有大量無效內容。

---

### 錯誤 18：使用 `fflush(stdin)` 當成可攜的清除方法

標準 C 沒有將它定義為通用輸入清除操作。

---

### 錯誤 19：認為 `%d` 成功後整行一定已被消耗

後面可能仍有非數字字元。

---

### 錯誤 20：混用 `%d` 與 `%c` 時忘記前一個換行

下一個 `%c` 可能立即讀到 `'\n'`。

---
